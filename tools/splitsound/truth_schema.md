# 正解データの形式 (Split Sound 実験)

設計: `docs/request/ver10/resolve_ss1.md` §3.3
置き場: `docs/request/ver10/ss1_truth/<素材ID>.jsonl` (例: `S1.jsonl`)

## 1 行 1 発話の JSONL

```json
{"start": 12.34, "end": 15.80, "speaker": "host", "text": "いやーもうF14でしょこれは"}
{"start": 21.05, "end": 24.60, "speaker": "game", "text": "ジョーカー隊、着艦せよ"}
{"start": 40.10, "end": 41.20, "speaker": "other", "text": ""}
```

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `start` / `end` | 数値 (秒) | 発話の実時間。**素材の先頭 (0.0) 基準**。聞こえ始め〜聞こえ終わりを取る |
| `speaker` | 文字列 | 下表のいずれか |
| `text` | 文字列 | **`host` / `sub` のみ必須** (CER の正解)。`game` / `other` は空でよい |
| `conf` | 文字列 (任意) | 下書きの候補の確度 (`low` = 確認してほしい行)。評価では見ない |
| `unconfirmed` | 真偽 (任意) | 候補のまま確認していない行の印。評価では見ない |
| `unclear` | 真偽 (任意) | 人が聞き取れなかった行。**CER の採点から外す** (本文に `[?]` があれば自動で同じ扱い) |
| `overlap` | 真偽 (任意) | 同じ区間に重ねて足した行の印。評価では見ない (記録用) |
| `added` | 真偽 (任意) | 空き区間に人が足した行の印。評価では見ない (記録用) |

> **行の時刻は重なってよい。** 同じ区間を 2 人が喋ったときは 2 行に分ける (下の節)。

### `speaker` の選び方

| 値 | 何を入れるか | 評価での扱い |
| --- | --- | --- |
| **`host`** | **動画に残したい人の声。** 配信者本人、**共演している他の配信者**、および会話相手 (出展者・スタッフ・インタビュー相手) | **残したい声 (H)** |
| `sub` | 配信者を**区別して記録したいときだけ**使う (本人 = host / 共演者 = sub)。区別が要らなければ全部 `host` でよい | **`host` と同じ (H に入る)** |
| `game` | 人の声が無い区間 (ゲーム音・BGM・SE・環境音・人混みのざわめきだけ) | 残したくない音 |
| `other` | **残したくない人の声。** 場内アナウンス、通行人、他ブース・他席の会話、TV やトレーラーの音声 | 残したくない音 |

> **複数人の配信 (コラボ・IRL) では、共演者の声も `host`** である。
> 「配信者が話している個所だけカット」の目的は**残したい声を残すこと**なので、
> 誰が喋っているかではなく**残したいかどうか**で決める。
> 共演者を別扱いしたい場合だけ `sub` を使う (評価は同じ)。

- `//` で始まる行と空行は読み飛ばす (メモを書いてよい)。
- 時刻の基準は `output/_splitsound/<素材ID>/analysis_source.wav` の先頭。
  この WAV が全条件の共通入力なので、**この 1 本だけを聞いてラベルを付ければよい**。

## S1 / S2 では「配信者の発話だけ」付ければ足りる (簡略化)

先頭に次の 1 行を置くと、**全区間にゲーム音が鳴っている**ものとして評価する。

```json
{"_meta": {"game_everywhere": true}}
```

S1 / S2 は現行のカット閾値で**無音が 1 件も出ない** (無音率 0.000 / `result_ss1.md` §2) ので、
これは実測に合っている。宣言すると「ゲーム音のみの区間」=「配信者の発話以外の全部」と決まり、
**`game` の行を 1 本も書かなくても M2 (ゲーム音のみ区間の残存率) と M4 が計算できる**。

- この宣言をした素材では **M6 (完全な無音に出たテロップ) は常に 0 件**になるため見ない。
- S3 のような静かな素材では**宣言しない** (本当に無音の区間があるため)。
- `speaker` が空の行は評価に入らない。下書きのまま混ざっても害が無いようにしてある。

## 作業ページ (おすすめの作り方)

```bash
python tools/splitsound/make_label_page.py --materials S1
```

- `output/_splitsound/S1/label.html` ができる。ブラウザで開くと
  `analysis_source.wav` を鳴らしながら、認識結果の各行の区分を確認・修正できる。
- `docs/request/ver10/ss1_truth/S1.draft.jsonl` も同時に書く (ページを使わず手で直す場合用)。
- キー操作: 時刻クリックで**その区間だけ再生**、
  <kbd>1</kbd> host / <kbd>2</kbd> sub / <kbd>3</kbd> game / <kbd>4</kbd> other (押すと次へ進む)、
  <kbd>Enter</kbd> 候補のまま確認済みにする、<kbd>0</kbd> 取り消し、
  <kbd>J</kbd>/<kbd>K</kbd> 前後、<kbd>R</kbd> もう一度、<kbd>Space</kbd> 再生/停止。
- 入力はブラウザに自動保存される (閉じても続きから)。
- 終わったら「ファイルで保存」→ `docs/request/ver10/ss1_truth/S1.jsonl` として置く。

### 区分の候補が入っている

`tools/splitsound/candidates/<素材>.json` があると、**区分の候補**を当て込んだ状態で
下書きとページを作る。候補は**認識結果の本文を読んだだけの推測**で、音は聞いていない。

- ページでは候補が**破線**で表示される (実線 = 自分で決めた / 確認済み)。
- `conf: "low"` の行には <kbd>low</kbd> の印が付く。**まずここだけ確認すれば足りる。**
- 「低確度だけ表示」「未確認だけ表示」で絞れる。
- 書き出した JSONL では、候補のままの行に `"unconfirmed": true` が残る
  (どこを人が確認したかが後から分かる。評価では見ない)。

### 3 段に分けてよい (どこで止めても、そこまでは使えるデータになる)

| 段 | 作業 | 得られる指標 | 目安 (10 分の素材) |
| --- | --- | --- | --- |
| **A** | `speaker` を確認・修正する (本文は直さない) | **M1 / M2 / M4** = **無音カットの判定** | 30〜60 分 |
| **B** | **`host` / `sub` の本文を直す** | **M3 (CER)** = **文字起こしの判定** | さらに 1〜2 時間 |
| C | 空き区間を聞いて、落ちている発話の行を足す | **M5 (取りこぼし率)** が正しくなる。B の CER もより正確になる | さらに 30 分 |

**段 A だけでも「分離で無音カットが良くなったか」は判定できる。** まず A を通すのが早い。

### 本文を直すときの決め (段 B)

本文は **CER (文字誤り率) の正解**になる。評価は
「`host` / `sub` の本文を時刻順に全部つないだ文字列」と
「生成されたテロップを時刻順に全部つないだ文字列」を比べるので、次が大事になる。

| 決め | なぜ |
| --- | --- |
| **聞こえたとおりに書く** (言い直し・言い間違い・フィラーもそのまま) | きれいな日本語へ直すと、**正しく認識できた方が誤りに数えられる** |
| 固有名詞は**正しい綴り**で書く | 「エルガト」を「エルガブ」と認識したのは**本当の誤り**なので、正解側は正しく書く |
| 数字は聞こえたまま (「1.1 キロ」) | 評価前に NFKC で全角/半角は揃えるので、どちらで書いてもよい |
| 句読点・記号は気にしない | 評価前に落とす |
| **行の区切りは気にしない** | 全部つないでから比べるため、区切り位置は CER に影響しない |
| `game` / `other` の本文は**空でよい** | 正解に入れない (残したくない音なので) |

> **絶対値より比較が大事**: フィラーを書くか書かないかで CER の絶対値は動くが、
> **全条件が同じ正解を使う**ので、C0 と C1 の**差**は正しく出る。
> §3.6 の判定は「相対 10% 以上の改善」なので、書き方を途中で変えないことだけ守ればよい。

### 同じ区間で 2 人が話しているとき

**行を分けて 2 行書く。時刻が重なっていてよい。**
ページでは <kbd>＋人</kbd> ボタンで同じ区間の行を足せる。

```json
{"start": 10.0, "end": 13.0, "speaker": "host", "text": "これすごいね"}
{"start": 12.0, "end": 14.0, "speaker": "sub",  "text": "ほんとだ", "overlap": true}
```

評価はこう扱う。

| 指標 | 扱い |
| --- | --- |
| M1 / M2 (無音カット) | 区間を**重ね合わせ (union) して**「残したい声がある時間」にする。重なっても二重に数えない |
| M3 (CER) | 本文を**開始時刻の順に繋ぐ**。上の例では「これすごいねほんとだ」が正解になる |
| M5 (取りこぼし) | 行ごとに、重なるテロップがあるかを見る |

| 迷ったとき | 決め |
| --- | --- |
| 片方が明らかに主で、もう片方は後ろでガヤガヤ言っているだけ | **主の 1 行だけ**書く (ガヤは背景音とみなす) |
| 2 人とも聞き取れて、内容も分かる | **2 行書く** (上の例) |
| かぶっていて**どちらも聞き取れない** | 1 行にして `[?]` (下の節) |
| 片方だけ聞き取れる | 2 行書き、**聞き取れない方の行だけ** `[?]` にする |

> **注**: 認識エンジンは 1 本の音声から 1 本の文字列しか出さないため、
> 2 人分を正解に書くと「もう 1 人分」は取りこぼしとして CER に乗る。
> これは**現状の限界を正しく映した数字**であり、全条件で同じ正解を使うので
> C0 と C1 の**差**は正しく出る (§3.6 の判定は相対改善で見る)。

### 聞き取れないときどう書くか

**人が聞き取れない区間は、正解を作れない。** 推測で書くと、
**正しく認識できていた方が誤りに数えられる**ため、無理に書いてはいけない。
`[?]` を入れて**採点から外す**。

| 状況 | 書き方 | 扱い |
| --- | --- | --- |
| **まったく聞き取れない** | <kbd>U</kbd> キーか <kbd>[?]</kbd> ボタン → 本文が `[?]` になる | その区間は **CER の採点から外れる**。区分 (残す/切る) は残るので M1 / M2 / M5 には使われる |
| **一部だけ聞き取れない** | 聞こえた部分を書いて `[?]` を混ぜる (例: `これってつまり[?]ってこと?`) | 同じ。**行まるごと**採点から外れる (部分採点はしない) |
| **ほぼ聞き取れていて 1〜2 文字が怪しいだけ** | `[?]` は入れず、**聞こえたとおり**書く | 通常どおり採点する |
| **喋っているのかどうかも分からない** (ざわめきの中の声かもしれない) | 区分を**空のまま**にする | 行ごと評価から外れる |

`[?]` が入った行では、**正解と生成テロップの両方**をその区間ごと外す (`evaluate.py`)。
片側だけ外すと、認識が正しく出していても挿入誤りとして数えられてしまう。

```text
検証 (tools/splitsound/evaluate.py):
  正解  「こんにちは」(0-2s) ＋ 聞き取れない [?] (5-7s)
  生成  「こんにちわ」(0-2s) ＋ 「まったく違う文字列がここに出た」(5-7s)
    両側から外す → CER 0.2  (誤り 1 文字 / 5 文字) ← 正しい
    正解だけ外す → CER 3.2  (正しく認識した分まで誤り扱い) ← 誤り
```

書き出した JSONL には `"unclear": true` が付き、`metrics.csv` には
**`unclear_rows` / `unclear_sec` / `cer_scored_ratio`** (= 採点できた割合) が出る。
聞き取れない区間が多い素材では、CER の絶対値をこの割合と一緒に読む。

### 空き区間について (段 C)

ページには**どの行にも入っていない時間** (既定 1.5 秒以上) が灰色の行で挟まっている。
認識がまるごと落とした発話はここに隠れており、**行を足さないと正解にも載らない**
(= 取りこぼしが無かったことになり、M5 が実態より良く出る)。

- 聞いて発話があれば「＋発話を足す」→ 開始/終了を微調整して区分と本文を入れる。
- 発話が無ければ**そのままでよい** (環境音だけの区間は書かなくても `game_everywhere` で扱える)。
- 書き出した行には `"added": true` が付く (後から「人が足した行」だと分かる)。

## 決め事

| 項目 | 決め |
| --- | --- |
| 区切る単位 | 息継ぎで切れるまで。**0.3 秒未満の間は切らない** |
| 笑い声・相槌 | **`host` に含める** (テロップにはならないが「残したい音」なので / §10 Q7) |
| 共演者 (複数人の配信) | **`host`** (区別したいときだけ `sub`) |
| 会話相手 (出展者・スタッフ) | **`host`** — インタビューは動画の中身なので残したい |
| 声とゲーム音/環境音が重なる区間 | `host` にする。評価では「残したくない音だけの区間」= `host` 以外として扱う |
| 環境音が鳴り続けている長い区間 | 1 行で長く取ってよい (`text` は空)。`game_everywhere` を宣言した素材では書かなくてよい |
| 迷った区間 | 空のまま (`speaker` が空の行は評価に入らない) |

> **指標の読み替え**: M2 は設計書で「ゲーム音のみ区間の残存率」と呼んでいるが、
> 実体は**「残したい声が無い区間の残存率」**である。
> IRL 配信では「環境音・人混みだけの区間」と読む。

## 作り方の近道

1. `run_conditions.py --conditions c0_baseline` を回す
   → `output/_splitsound/<素材ID>/c0_baseline/result.json` に認識結果が入る
2. その `asr.items` を JSONL へ写し、`speaker` を付けながら `text` を直す
   (ゼロから書き起こすより速い / §3.3)
3. `game` は時刻だけでよいので、ゲーム音が多い素材は時刻ラベルを厚めに取る

## 確認

`evaluate.py` は正解が無くても動くが、精度の指標 (M1〜M6) は空欄になる。
正解を置いてから再実行すれば埋まる。
