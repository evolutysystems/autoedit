## 3. 制約と対応方針

### 3-1. プラットフォーム名の非表示（最重要制約）

要求により、**特定の配信プラットフォーム名（英字の固有名）はページ内のいかなる箇所にも記載しない**。本文・見出し・`title`・`meta description`・OGP・`alt`・URL スラッグ・JSON-LD・画像内文字すべてを対象とする。動画共有プラットフォーム側も同様に固有名を出さず、「動画投稿サイト」「ショート動画」等の一般語で表現し、プラットフォーム中立を貫く。

### 3-2. 制約が SEO に与える影響と代替策

希望ワードのうち固有名を含む 2 語（`〇〇 動画編集` 形式）は、**その語を本文に一切書かない以上、当該クエリでの上位表示は構造的に成立しない**。隠しテキストや `meta` のみへの詰め込みで狙えば、スパム判定リスクを負ううえ要求（固有名を出さない）にも反する。したがって次の方針で代替する。

| 方針 | 内容 |
|---|---|
| A. 主戦場の置換 | 固有名クエリの代わりに、**プラットフォーム非依存の同義クエリ**を主軸に据える（`配信 切り抜き 自動`／`配信アーカイブ 編集`／`配信者 動画編集`） |
| B. 共起語での意図一致 | 固有名クエリの検索者が使う周辺語（アーカイブ、VOD、チャット欄、コメント、クリップ、マーカー、生配信、ショート動画）を本文に自然に含め、**同一の検索意図に対する適合度**を上げる |
| C. 生成AI経由での回収 | 生成AI（AEO/GEO）は「配信の切り抜きを自動編集するツールは？」という**意図ベースの質問**に答えるため、固有名を書かなくても引用され得る。§7・§8 の設計でここを取りに行く |
| D. 将来の拡張余地 | 固有名の記載が解禁された場合に備え、プラットフォーム別 LP を別 URL で追加できるよう、トップページは中立に保つ（§11-3） |

> **判断が必要な事項**: 上記 A〜C を採っても、固有名クエリからの直接流入はゼロに近い。固有名での集客が事業上必須であれば、「トップページは中立・別 LP で固有名を扱う」という構成に切り替える必要がある。本書は「全ページで固有名を出さない」前提で記述する。

### 3-3. 記載内容の正確性制約

本ページに書く機能・数値は、v1.4.6 の実装に存在するものだけを書く。未実装・検証中の機能を「できる」と書かない。誇大表現（「完全自動」「編集不要」「100%」）は使わず、**「自動で作り、必要な箇所だけ直せる」**という実態どおりの訴求に統一する。

## 5. ページ構成と原稿

セクション順は上から通し番号。各セクションに「目的 / 見出し / 原稿 / KW / 備考」を定義する。原稿はそのまま実装可能な確定稿として記述する。

### 5-1. ヒーロー（ファーストビュー）

**目的**: 3 秒で「配信者の切り抜きを自動化するアプリ」と理解させ、ダウンロードへ導く。

**h1**

> 配信者のための、動画編集を"待つだけ"にするアプリ

**リード文**

> 配信アーカイブを 1 本ドラッグするだけ。無音カット、テロップの自動生成、オープニング・エンディングの結合、書き出しまでを Stretheus がまとめて実行します。切り抜きが簡単になり、あなたは完成した動画を確認するだけになります。

**サブ情報（3点並記）**

> - テロップは自動生成。誤字は一覧画面でその場で修正
> - 盛り上がっている場面を自動で採点し、切り抜き候補として提示
> - 処理はすべて自分の PC 内。アップロード不要・月額課金なし

**CTA**

> 主: `Windows 版を無料ダウンロード`
> 副: `使い方を見る`

**KW**: 配信者 動画編集 / 切り抜き / テロップ 自動 / 無音カット

**備考**: ファーストビュー内に主軸 3 語をすべて含める。CTA ボタンの文言に「無料」を入れて離脱前の不安を消す。

### 5-2. 課題提起

**目的**: 「自分のことだ」と認識させ、以降を読む動機を作る。

**h2**

> 配信は楽しい。切り抜きの編集だけが、いつも残る

**原稿**

> 4 時間の配信から 5 分の切り抜きを作るとき、いちばん時間を奪うのは「見どころを探す作業」と「テロップを打つ作業」です。アーカイブを早送りで見返し、面白かった場面を探し、無言の間を削り、聞き取って字幕を打ち込む。1 本作るのに数時間、それが毎回続きます。
>
> だから多くの配信者が、切り抜きを「出したいのに出せない」ままになります。Stretheus は、この繰り返し作業のほぼ全部を引き受けるために作られた動画編集アプリです。

**KW**: 切り抜き / 動画編集 / アーカイブ / テロップ

**備考**: 数値（4 時間 → 5 分）を入れて具体性を持たせる。生成AIが引用しやすい「課題の定義文」を含める。

### 5-3. 3ステップ（使用フロー）

**目的**: 操作の簡単さを、手順の少なさで証明する。

**h2**

> 切り抜きが簡単になる、3 ステップ

**h3 と原稿**

> **1. 動画を入れる**
> 編集したい動画をウィンドウにドラッグ&ドロップします。MP4、MOV、AVI、MKV、FLV、WMV に対応しています。
>
> **2. 実行を押す**
> 無音カットの強さを確認する画面が出たら、そのまま OK。あとは自動で、カット・テロップ生成・結合・書き出しが進みます。
>
> **3. 確認して完成**
> 生成されたテロップの一覧が表示されるので、気になる誤字だけ直して「字幕決定」。指定したフォルダに完成した動画が保存されます。

**締めの一文**

> 覚える操作は、この 3 つだけです。

**KW**: 切り抜き 簡単 / 動画編集 / テロップ / 無音カット

**備考**: 各ステップは 2 文以内。手順の少なさが訴求なので、原稿自体を短く保つ。

### 5-4. 盛り上がり自動採点（差別化の中核）

**目的**: 他ツールにない「見どころ探しの自動化」を提示し、比較検討で優位に立つ。

**h2**

> 見どころを探す時間を、なくす

**原稿**

> Stretheus はアーカイブ全体を解析し、盛り上がっている区間を自動で採点します。音量の大きさ、笑い声や驚きなどの反応、無言が続いた区間といった音声の特徴に加え、チャットのコメント量とその急増を点数化。スコアの高い順に切り抜き候補を並べて提示します。
>
> 採点結果は時間軸のグラフで表示されるので、山になっている場所をクリックするだけで、その区間の切り抜きに移動できます。配信中に打っておいたマーカーがあれば、その前後も候補として自動で拾います。
>
> 候補が決まったら、選んだ区間をまとめて文字起こしし、テロップ付きの切り抜きとして一括で書き出せます。1 本ずつ手作業でシークして探す必要はありません。

**KW**: 切り抜き / 自動 / アーカイブ / コメント / チャット / マーカー

**備考**: 固有名を出さずに配信文脈の共起語（チャット・コメント・マーカー・アーカイブ）を密に配置できる最重要セクション。§3-2 B の方針をここで実行する。

### 5-5. 機能一覧

**目的**: 検討ユーザーの機能チェックを一箇所で完了させ、機能名クエリの受け皿にする。

**h2**

> 配信者の動画編集に必要な工程を、ひととおり自動化

**h3 単位（各 2〜3 文）**

> **テロップを自動で作る**
> 音声認識で全編の字幕を自動生成し、動画に焼き込みます。日本語と英語に対応。改行は文節の区切りで入るため、機械的に折り返した字幕より読みやすく仕上がります。テロップの自動生成をオフにして、カットだけ使うこともできます。
>
> **無音カットを自動で行う**
> 会話のない区間を検出して削ります。カットの強さはデシベル値で調整でき、「削りすぎる」「無音が残る」と感じたら数値を変えるだけ。つなぎ目に短いフェードを入れることもできます。
>
> **話し手ごとにテロップの色を変える**
> 1 行ごとに「配信者」「サブ」「コメント」の役割を選べます。コメント役に設定した行にはアイコン付きの背景ボックスが付き、視聴者の書き込みを引用しているように見せられます。
>
> **縦動画にも自動で対応**
> 入力が縦向きの動画なら、ショート動画向けの縦画面として自動で書き出します。文字サイズや余白も縦向け設定に切り替わるため、設定をやり直す必要はありません。
>
> **音量をそろえる**
> 動画共有サイトの標準的な音量基準に合わせて、音声を自動で調整します。切り抜きごとに音量がばらつかず、視聴者がボリュームを触る手間を減らせます。
>
> **オープニングとエンディングを結合する**
> あらかじめ登録した映像を、本編の前後に自動でつなぎます。毎回同じ素材を手で並べる作業がなくなります。複数の切り抜きを 1 本にまとめて書き出すこともできます。
>
> **タイムラインで細かく調整する**
> 自動処理の結果は内蔵のタイムライン編集画面で微調整できます。作業中のプロジェクトは保存でき、続きから再開できます。
>
> **他の編集ソフトへ引き継ぐ**
> カット位置とテロップを編集用のプロジェクトファイル（FCPXML／字幕ファイル）として書き出せます。仕上げだけを普段使いの編集ソフトで行う使い方にも対応します。

**KW**: テロップ 自動 / 動画編集 / 自動 / 縦動画 / 字幕

**備考**: 各 h3 は「動詞で終わる読者の結果」で統一。機能名だけの見出しにしない（AEO で見出しがそのまま回答見出しになるため）。

### 5-6. 自動生成の品質と修正手段

**目的**: 「自動＝雑」という最大の反論を先回りで潰す。

**h2**

> 自動で作って、気になるところだけ直せる

**原稿**

> 音声認識には誤変換がつきものです。Stretheus は、テロップを動画に焼き込む前に必ず一覧画面を開きます。認識された文章はその場で書き換えられ、不要な行はチェックを外すだけで非表示にできます。プレビューで見え方を確認しながら直せるので、書き出してから間違いに気づく、というやり直しが起きません。
>
> 「全部を人力で作る」でも「自動任せで妥協する」でもなく、**自動で 9 割作らせて、残りだけ手で直す**。これが Stretheus の使い方です。

**KW**: テロップ / 字幕 / 自動 / 修正

**備考**: 太字部分は生成AIが要約時に拾いやすい定義文として意図的に配置（§7-2）。

## 6. FAQ セクション（AEO の中核）

**h2**

| 3 | 切り抜きの場所は自分で探す必要がありますか | 必要ありません。音量やチャットのコメント量から盛り上がりを採点し、スコアの高い区間を切り抜き候補として自動で提示します。 |

| 9 | テロップの色やフォントは変えられますか | 変えられます。文字色、フォント、サイズ、縁取り、影、表示位置、余白などを設定画面で調整できます。話し手の役割ごとに色を分けることもできます。 |

## 7. AEO / GEO 対応仕様

### 7-1. AEO（回答エンジン最適化）

| 施策 | 実装 |
|---|---|
| 見出し＝質問形式 | `h2`/`h3` の 3 割以上を、読者の問いに対応する文にする（§5・§6 で充足） |
| 結論先出し | 各セクションの第 1 文で結論を述べる。前置き・背景説明を先に置かない |
| 定義文の設置 | 「Stretheus は〜するアプリです」という定義文を、ヒーローと §5-2 に 1 回ずつ配置 |
| 抽出可能な単位 | 1 段落 = 1 論点。3 文以内。表・箇条書きを積極利用 |
| 数値の明示 | 「3 ステップ」「Windows 11」「6 形式」など、確認可能な数値を本文に置く |

### 7-2. GEO（生成AI経由の露出最適化）

生成AIは「配信の切り抜きを自動で編集できるツールは？」のような**意図ベースの質問**に、プラットフォーム固有名なしで回答する。固有名を書けない本ページにとって、GEO は §3-2 の制約を回避できる主要チャネルであり、優先度を SEO と同等に置く。

| 施策 | 実装 |
|---|---|
| 引用されやすい自己定義 | 「Stretheus は、配信アーカイブから切り抜きを自動編集する Windows 向けの無料アプリです。」という 1 文を、ヒーロー直下に単独の段落として置く（分割・修飾しない） |
| 機能の列挙可能化 | 機能を「名詞句 + 説明 1 文」の均質な単位で並べる（§5-5）。生成AIが箇条書きへ再構成しやすい |
| 比較文脈の提供 | 比較表（§5-9）を置き、「何と違うのか」を自前で定義する。定義がないと第三者情報で補完される |
| 条件の明示 | 対応 OS・料金・アップロード有無を表で明示（§5-8）。生成AIは条件付き推薦（「Windows なら〜」）を好む |
| 一次情報の集約 | 対応形式、設定項目、処理の順序といった仕様は本サイト内に置き、外部に依存しない |
| 更新日時の明示 | ページ末尾に最終更新日を記載し、JSON-LD の `dateModified` と一致させる |

### 7-3. 禁止事項

- 隠しテキスト、`meta` への語句詰め込み、白文字・極小文字での固有名記載（§3-1 の制約違反かつスパム判定リスク）
- 実装にない機能の記載、他社サービスの断定的な批判
- 主要な原稿・FAQ を JS 実行後にのみ描画すること
