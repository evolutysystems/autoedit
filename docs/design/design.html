1. システム概要

配信アーカイブから YouTube 向けのフルテロップ切り抜き動画を作る工程を自動化する Windows デスクトップアプリ。 利用者の操作は「素材を選ぶ → 実行 → 編集画面で直す → 決定」の 4 手に収める。

OS

Windows 11

Python

3.14

GUI

PySide6

FFmpeg

同梱 (PATH 非依存)

音声認識

faster-whisper / CPU

サーバー

Stretheus API

提供する 3 つの実行経路

経路入口入力概要
A クリップ用 1 本編集「クリップ用」タブ動画 1 本 正規化 → 無音検出 → 文字起こし → Timeline 編集 → 書き出し
B アーカイブ切り抜き「アーカイブ切り抜き用」タブTwitch VOD / 長尺動画 全長採点 → 候補区間の前処理 → 一括編集 → 結合して出力
C 編集の再開各タブ「続きから」プロジェクト JSON 素材を復旧 → Timeline 編集 → 書き出し

付随機能: 縦動画プロジェクトの作成 / DaVinci Resolve 出力 (.fcpxml + SRT) / トラッキングぼかし / 透かし。

2.5 進捗表示

  • FFmpeg は必ず utils/progress.run_ffmpeg_progress 経由 (ffmpeg_runner.execute が唯一の呼び出し元)。-progress pipe:1 を読む
  • 工程の粒度は PipelineContext.begin_step / end_step、 工程内の細かい進捗は progress_subcallback
  • 無応答が ffmpeg.progress_timeout_sec を超えたら打ち切る
  • 工程ごとの所要は utils/stage_timer が 1 行でまとめる

4. 主要クラス・データモデル

PipelineContext (工程間で受け渡す唯一の状態)

PipelineContext
 ├─ input_path / working_dir / output_path
 ├─ settings                   実行用コピー (キャンバス解決済み)
 ├─ progress_callback / total_steps / current_step / begin_step / end_step
 ├─ current_video_path()       直前の工程が作った動画
 ├─ asr_audio_path() / build_asr_audio()
 ├─ timeline / project_path / project_created_at
 ├─ output_profile             {is_portrait, orientation, width, height}
 ├─ project_id                 ログ送信の単位
 ├─ watermark_required         透かしを焼くか (サーバー応答由来)
 └─ cleanup()                  中間ファイルの後始末

Timeline

Timeline
 ├─ width / height / orientation
 ├─ tracks[]
 │    ├─ V1   ベース映像 (OP / 本編の残す区間 / ED)。最背面固定
 │    ├─ V2+  オーバーレイ映像・画像 (z_order)
 │    ├─ A1   V1 にリンクした音声 (独立した時刻を持たない)
 │    └─ S1.. 字幕 (役割別。既定 3 / 最大 timeline.subtitle_tracks.max_tracks)
 ├─ source    元動画・編集点メタ・ぼかし指定・crop 指定
 └─ Clip = MediaRef (素材と素材内時刻) + Transform (位置・大きさ) + use
  • プロジェクト JSON は schema_version = 1。未知の版は TimelineError、古い版は移行
  • 種別はファイル名の接尾辞 (.archive) で決まり、取り違えを読込時に弾く
  • 追従ぼかしの結果は重いので JSON へ入れず blur/store.py が別ファイルへ持つ

テロップの文字色の決定順 (timeline/subtitle_style.py)

  1. クリップ個別の色 (SubtitleClip.color)
  2. トラックの既定色 (Track.color / ヘッダの色見本)
  3. 役割の色 (subtitle.own/sub/comment_subtitle_color)
  4. フォールバック (配信者色)

焼き込み・プレビュー・Resolve 出力はすべてこの 1 か所から引く。 役割は載っているトラックが決める一方通行で、編集画面の「役割」コントロールは既定で出さない。 フォント・サイズ・配置は subtitle.* を既定とし、縦動画では vertical.* が上書きする。

5. setting.json 定義

既定値の唯一の出どころは settings_window.DEFAULT_SETTINGS。 setting.json だけに書いた新キーは load_settings → save_settings で消えるため、 設定を足すときは必ず両方を直す。

互換性方針

  • _merge_with_defaults はセクション単位の浅いマージ。既存のユーザー値を温存する
  • 入れ子キーの欠落は各パッケージの config.py が既定へ落とす
  • 既定値を変えて既存値も直したいときは移行フラグで 1 回だけ書き換える (metric_migrated / ripple_delete_migrated ほか)
  • 既存キーの意味・型は変えない。意味を変えるなら新しいキーを足す

6. 外部連携

相手内容失敗時
Stretheus APIログイン (OAuth 認可コード / 匿名端末)・ポイント・課金・ログ送信 5xx・接続失敗は ApiOfflineError で縮退。編集と書き出しは止めない
StripeCheckout / カスタマーポータル (ホスト画面へ誘導)カード情報はアプリで扱わない
TwitchOAuth・所有判定・VOD / チャット取得 (twitch-dl)・ストリームマーカー TwitchError。ローカル動画経路は影響なし
GitHub Releases自動更新 (インストーラ取得・起動)静かにスキップ
  • JWT は %LOCALAPPDATA%\Stretheus\auth.dat へ Windows DPAPI で保存。トークンはログへ出さない
  • ポイントは「出力 1 回につき予約 → 成果物の完成で確定 / それ以外で取消」。 透かしの要否はサーバーの応答だけで決める
  • ログは telemetry がファイルへ 1 本書くだけ (オフラインでも成功)。 送信は log_sender が低優先度で行う

7. エラー処理方針

AutoEditError
 ├─ ConfigError          設定不整合
 ├─ InputError           入力動画・プロジェクトが無い / 読めない
 ├─ FFmpegError          command / stderr_tail / returncode
 ├─ DiskSpaceError       path / free / required
 ├─ SubtitleError        テロップ生成
 ├─ PipelineCancelled    利用者の意図による中断
 ├─ ExportError          Resolve 出力
 ├─ TwitchError          ログイン / 所有判定 / twitch-dl
 ├─ TimelineError        モデル・JSON・編集の前提違反
 └─ ApiError             status / code / retry_after
      ├─ ReauthRequiredError  401 再ログインが必要
      └─ ApiOfflineError      到達不能 (縮退)
区分方針
入力不正工程前に ffprobe で確認し、理由を名指しして中断
容量不足作業先と出力先を開始前に確認。足りなければ即中断 (握り潰さない)
FFmpeg 失敗戻り値 != 0 を例外化し、コマンドと stderr 末尾をログへ
OP/ED 未設定例外にせずスキップして継続
正規化・字幕・プロジェクト保存の失敗記録して続行 (出力は作れる)
利用者のキャンセルポイントを戻し「中断」として記録
想定外例外最上位で記録して再送出。GUI は対象と理由を添えて表示
中間ファイル成否に関わらず finally で後始末。残骸は次回起動時に掃除

8. ログ出力方針

  • 標準 logging のみ。コンソール + <logging.log_dir>/autoedit_YYYYMMDD.log (5MB x 5 世代)
  • 形式 %(asctime)s [%(levelname)s] %(name)s: %(message)s / レベルは logging.level (既定 INFO)
  • FFmpeg コマンド全文は DEBUG。例外は logger.exception
  • log_dir はカレント相対。配布時はショートカットの作業フォルダか設定値を運用に合わせる
  • サーバーへ送るログとローカルログは別系統

9. 配布・テスト

  • PyInstaller の onedir で Stretheus.exe (src/main_window.spec) → Inno Setup のダウンローダ型インストーラ (installer/AutoEdit.iss)
  • src/version.py と .iss の MyAppVersion を必ず一致させる
  • FFmpeg / ffprobe は同梱。CUDA ランタイムは同梱しない (CPU 実行に統一)
  • 手順は docs/HowToRelease.md と installer/README.md (後者が正典)
  • テストは標準 unittest。python -m unittest discover -s tests。 対応表と不足観点は docs/design/test_matrix.md
