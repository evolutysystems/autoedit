## 1. ① AI のテロップを正しい枠へ置く (`ai/plan_applier.py`)

### 1.1 `pieces[0]` をやめ、連続する片をまとめる

```python
pieces = _source_pieces(timeline, index, item["source_start"], item["source_end"])
start, end = pieces[0]          # ← 先頭の破片しか見ていない
```

無音カット (編集点モード) では、素材の 1 区間が複数の Timeline 片へ割れる。
**割れた片は Timeline 上では隣接している** (間の無音は取り除かれて詰められるため)。
実測でも `TL 69.44 + 0.33 = 69.77` と次の片の頭が一致していた。

したがって正しい枠は**片の全体**である。

```python
start, end = _span_of(pieces, tolerance)   # pieces[0][0] 〜 pieces[-1][1]
```

片の間に許容差を超える隙間があれば (別シーンが挟まるなど)、
**最も長い連続した一続き**を採る。壊れた写像で全体を 1 本に伸ばさないための保険である。

### 1.2 既存テロップの再利用に条件を付ける

```python
existing = _subtitle_at(timeline, start, end)   # 少しでも重なれば拾う
```

`_subtitle_at` は重なりが `_EPS` を超えれば採用する。そのため
**0.30 秒の枠が 12 文字の本文を飲む**。再利用は「同じ瞬間を指しているとき」に限る。

| 条件 | 式 |
|---|---|
| AI の枠の大半を覆う | `overlap / (end - start) >= reuse_min_ratio` |
| 既存の枠の大半が中に入る | `overlap / existing.duration >= reuse_min_ratio` |

両方を満たさなければ**再利用せず新規に足す**。片方だけだと、長い既存テロップが
短い AI テロップを飲む (または逆) を防げない。

### 1.3 読めない枠へは書かない

枠の長さに対して本文が長すぎる場合は、`A5` に理由を付けて**落とす**。
黙って読めないテロップを出すより、レポートに残して人が気付けるほうがよい。

| 判定 | しきい値 |
|---|---|
| 枠が短すぎる | `end - start < min_display_sec` → `drop "too short"` |
| 文字が詰まりすぎ | `len(text) / (end - start) > max_chars_per_sec` → `drop "too dense"` |

実測では 8 本が毎秒 20 文字を超えていた。①の 1.1 で枠が本来の長さに戻るため、
この判定で落ちる本数自体が減る見込みである (0.30 秒 → 素材 4.58 秒ぶんの枠へ)。

### 1.4 設定 (`ai.plan.subtitle`)

```json
"subtitle": {
  "reuse_min_ratio": 0.6,
  "piece_gap_tolerance_sec": 0.05,
  "min_display_sec": 0.4,
  "max_chars_per_sec": 20
}
```

* `reuse_min_ratio = 0.6`: 「同じ瞬間」と言える重なり。0.5 では半分ずれた枠を拾う
* `min_display_sec = 0.4`: 1 文字でも読めない下限。`timeline.min_clip_sec` とは別物
  (あちらは映像クリップの下限)
* `max_chars_per_sec = 20`: 日本語テロップの実用上限。実測の 8 本がここに当たる

`plan_applier` は今まで `timeline_config` だけを見ていた。`ai.plan` を読むため
`from . import config as ai_config` を足し、`apply_plan` で解決して `_apply_subtitles` へ渡す。

## 2. ② 文字起こしに上限を付ける (`ai/context_builder.py`)

### 2.1 何が壊れているか

```python
def _merge_transcript(items, gap):
    for item in items:
        if merged and item["start"] - merged[-1]["end"] <= gap:
            merged[-1] = {...}      # 長さも文字数も上限が無い
```

実測: **99 件 → 1 件 / 149.1 秒 / 1,538 文字。**
AI は「149 秒のどこで言ったか」を知れないため、`source_start` / `source_end` は推測になる。

### 2.2 上限を 2 つ入れる

```python
def _merge_transcript(items, gap, max_sec=0.0, max_chars=0):
```

結合した結果が `max_sec` または `max_chars` を超えるなら**結合しない** (新しい件にする)。
0 を渡せば従来どおり無制限 = 回帰の逃げ道を残す。

| 設定 | 値 | 根拠 |
|---|---|---|
| `merge_transcript_max_sec` | **6.0** | テロップ 1 本の実測尺 (中央値 2.2 秒) の数本ぶん。AI の時刻の粒度がこれ以下になる |
| `merge_transcript_max_chars` | **40** | `max_line_length 20 × subtitle_max_lines 2` = テロップ 1 本の上限。**AI が見る粒度と出す粒度を揃える** |

`merge_transcript_gap_sec = 1.0` は**変えない**。無音で切る役は残す。

### 2.3 トークンへの影響

実測の 149 秒ぶんで 1 件 → 約 25〜40 件。1 件あたり約 20 トークンなので **+500〜800
トークン / シーン**。7 シーンで +約 5,000 トークン。`ai.budget.max_input_tokens`
は 60,000 で、立案の実測入力は 1 万台だったため収まる。

## 2.5 ④ テロップをどこまで AI に触らせるか (`ai.plan.subtitle_mode`)

### 2.5.1 わかったこと

**`ai.plan.subtitle_mode` は語彙だけあって、どこからも読まれていなかった。**
`plan_schema.SUBTITLE_MODES = ("full", "key", "none")` が定義され、
`ai/config.py` に既定 `"full"` もあるのに、`planner` は常に `subtitles` を受け取り、
`plan_applier` は常にそれを当てていた。

そして AI は**文字起こしを写すのではなく、作り直していた**。

| 計測 (plan のテロップ 86 件) | 値 |
|---|---|
| 文字起こしの全文にそのまま含まれる | **27 件 (31%)** |
| AI が言い回しを作り直した | **59 件 (69%)** |

```
AI  'あの 底辺チームからね 這い上がってやろうっていう'
元  '辺チームからね這' + 'い上がってやろうっていう気'
```

プロンプトには「テロップの本文は与えられた文字起こしをそのまま使う。
言い回しを作り変えない」と書いてある。**守れなかったのは②が原因**である。
149 秒 1 件の塊を渡していたため、AI は区切りを自分で作るしかなかった。

つまり AI は**既存処理がすでにやっている仕事を、より悪い精度でやり直していた**。

### 2.5.2 決めたこと

利用者の指示 (2026-11-25):

> AI が最初に調査した動画の盛り上がっている箇所を切り抜いて、
> 既存の処理で文字起こしする感じです。

**既定を `key` (見た目だけ) にし、`subtitle_mode` を実際に効かせる。**

| モード | `planner` の前置き | `plan_applier` の振る舞い |
|---|---|---|
| `full` | 本文も追加も任せる (従来) | 従来どおり |
| **`key`** (既定) | 本文は変更されないと伝え、**動きを付けるテロップだけ挙げさせる** | 重なった既存テロップの**見た目だけ**直す。本文・時刻・役割は触らない。足さない |
| `none` | `subtitles` は空にすると伝える | 全て `drop "subtitle_mode none"` |

* **役割も変えない。** 役割を変えるとトラックが移る (`ChangeSubtitleRole`) ため、
  文字起こしが S1 から出てしまう
* `key` では「動きを付けないテロップは `subtitles` に書かない」と伝えるので、
  **出力トークンが減る** (実測の 86 件 → 山の 1〜2 本)
* 前置きがモードで変わるため、`cache_prefix_id` に
  モードを足す (`edit_plan-v1-key`)。キャッシュを混ぜない
* `track_role = comment` の AI テロップ (視聴者コメントの引用) も `key` では
  足されなくなる。欲しくなったらここを見直す

### 2.5.3 ①との関係

①は**無くならない**。`key` でも「どの既存テロップに見た目を付けるか」を
時刻で突き合わせるため、`_span_of` (割れた片をまとめる) と
`_subtitle_at` の重なり比 (同じ瞬間だけ拾う) が要る。
①が無ければ `key` でも 0.30 秒の破片に重なった**別のテロップ**へ動きが付く。

## 2.6 ⑤ 工程の整理 — シーン評価を切り、レビューを有効にする

利用者の指示 (2026-11-26):

> AI が既存の機械的処理では見抜けない動画の面白ポイントを抽出してくれればいいです一旦。
> …4 を切ってください。7 のレビューは必要です。

### 2.6.1 シーン評価 (`sceneEval`) を切る

採点スイープ (`sceneScan`) が**映像を見て**山を挙げるようになったため、
**文字起こしと数値だけで候補を再採点する**この工程は役割が重なる。

| | 入力 | やること |
|---|---|---|
| `sceneScan` (工程 1.5) | **静止画 16 枚** + 音量 + コメント | 山を**見つける** |
| `sceneEval` (工程 4) | 文字起こし + 数値 (映像は見ない) | 候補に**点を付け直す** |

`ai.scene_eval.enabled = false` を足し、`scene_finder.evaluate` で効かせる。
**縮退の道はもともと在った** (「AI が失敗したら既存の採点だけで順位を付けて続行する」
`resolve1.md` §11.2) ので、そこへ合流させるだけで済む。

* `provider = None` と同じ扱いにする。候補は**落とさない** (`_unevaluated` が中立の軸で残す)
* **保存済みの評価 (`<project>.ai.json`) も使わない** (`reuse = False`)。
  切ったのに前回の AI の点が効くと「何が順位を決めたのか」が読めなくなる

### 2.6.2 レビュー (工程 7) を有効にする

`ai.review.enabled` を `false` → **`true`**。

役は既定のまま `director` / `critic` / `viewer` / `platform` (`qa` は機械の検査のみ)。
`critic` だけ `review_critic` = **opus** を希望する。`max_rounds = 2` だが、
**直すところが無ければ 1 往復で止まる**ので常に 2 往復するわけではない。

### 2.6.3 呼び出し回数と費用

`ai.cost.max_calls_per_project` は VOD 1 本ぶんの上限である
(`UsageTracker` はワーカーが 1 本持ち、3 つの出力先をまたぐ)。

| 工程 | 回数 | モデル |
|---|---|---|
| 採点スイープ | 14 | sonnet |
| 構成 + 編集指示 | 6 (出力先 3 x 2) | **opus** |
| シーン評価 | **0** (切った / 以前は 1〜4) | — |
| レビュー | **12〜24** (役 4 x 往復 1〜2 x 出力先 3) | sonnet 3 + opus 1 / 往復 |
| 合計 | **32〜44** | |

**既定の 20 では足りず、お手元の 40 でも 2 往復 (44 回) で足りない。**
`max_calls_per_project` を **60** へ上げる。途中で上限に当たると
レビューが中途で切れ、どこまで見たのか分からない報告になるため、
上限が設定された流れを壊さない値にする。

見積りの実費は **1 本あたり $1.0〜1.4** (従来 $0.49 + スイープ $0.15 +
レビュー $0.4〜0.8)。**サーバーの `MaxUsdPerDay` は 2.0** なので、
この構成では **1 日 1 本**が目安になる。安くしたい場合は
`ai.review.max_rounds` を 1 にすると約 $0.2〜0.4 下がる。

> `projectId` はクライアントから送っていないため、サーバー側の
> `MaxCallsPerProject: 40` は現状効いていない。効かせるなら
> `AiRequest.project_id` を埋める必要がある (別件)。

## 3. ③ カットで消えた無音を「間」として数えない (`modules/subtitle_generator.py`) — **見送り**

> **2026-11-25: 利用者の判断で実装しない。**
> 「文字起こしは既存の処理でいい。安定しているので」。
>
> `subtitle_generator` は**AI を使わない通常の書き出しも通る**道であり、
> 長く安定して使われている。直す価値はあるが、AI 編集の不具合を直すために
> そこを触る必要は無い (①②は `ai/` の中だけで閉じている)。
>
> 以下は**調べた結果の記録**である。手を付けるときはここから始められる。
> 残る症状: `'ド'` (0.33 秒) / `'ライブアウトからでしょまず走'` / `'る'` の 3 本割れ。

### 3.1 何が壊れているか

`regroup_items_by_length` は語の間 (`pause`) を**素材時間**で測る。

```python
pause = float(word["start"]) - last_end
torn = split_max_pause_sec > 0 and pause >= split_max_pause_sec
if over or far or torn or (enough and soft):
```

`torn` は**下限文字数で塞げない絶対の区切り**である (疎な発話が何十秒も 1 本に
繋がるのを防ぐために入れた / `docs/quality/kensyou`)。

ところが**無音カットで取り除かれた無音も `pause` に入る**。実測の例:

```
'ド'            素材 132.877-133.207
'ライブアウト…'  素材 142.070-143.768      素材の間 = 8.86 秒 → torn で必ず切れる
```

この 8.86 秒は**丸ごとカットで消えている**。Timeline 上では
`69.44 + 0.33 = 69.77` と**間が 0** であり、視聴者には「間」として存在しない。
存在しない間で区切るため、`'ド'` が 1 文字のテロップとして取り残される。

### 3.2 実効の間で測る

取り除かれた無音を引いた**実効の間** (= Timeline 上の間) で判定する。

```python
effective = _kept_between(keep_segments, last_end, word["start"])
```

`keep_segments` は既に引数で受けており、`_resolve_word_cut` が同じ列を
`cursor` で走査している。`last_end` と `word.start` の**間に残っている**
カットの合計長がそのまま Timeline 上の間になる。

| 判定 | 変更前 | 変更後 |
|---|---|---|
| `torn` (絶対に切る) | 素材の間 | **実効の間** |
| `paused` (間で切る) | 素材の間 | **実効の間** |
| `glued` (間が無いので繋ぐ) | 素材の間 | **実効の間** |
| `far` (`max_cut_gap_sec`) | 素材の間 | **変えない** |

`far` だけ素材のままにする。あれは「**取り除かれた無音**がこれを超えたら文脈が切れた
とみなす」という設定であり、消えた量そのものを見るのが定義である (既定は 0 = 無効)。

### 3.3 直るか

`'ド'` の例を追う。

| 語 | 実効の間 | `torn` | `enough and soft` | 結果 |
|---|---|---|---|---|
| `'ライブアウト…'` | 0 秒 | 立たない | `buf_len = 1 < 16` | 繋ぐ |
| `'る'` | 0 秒 | 立たない | `buf_len = 15 < 16` | 繋ぐ |

→ `'ドライブアウトからでしょまず走る'` (16 文字) の 1 本になる。
上限 (40 文字) までは `over` も立たない。

### 3.4 回帰の範囲

**無音カットで実際に無音が取り除かれた箇所でだけ**挙動が変わる。
`keep_segments` が連続している (カットしていない) 場合は実効の間 = 素材の間であり、
**従来と完全に同じ**。カットしない書き出しと既存テストは影響を受けない。

## 4. 採らなかった案

| 案 | 却下理由 |
|---|---|
| ① `pieces` の中で**最も長い片**を使う | 1 本は読めるようになるが、AI が指した区間の一部しか覆わない。隣接している片をまとめれば全部覆える |
| ① 既存テロップの枠を**伸ばす** | 既存テロップは文字起こしであり、AI の都合で時刻を動かすと文字起こしのほうが音声と合わなくなる |
| ② 文字起こしを**結合しない** (99 件そのまま) | トークンは足りるが、1 文字〜数文字の破片 (③の産物) がそのまま AI へ渡る。③を直すまでは逆効果 |
| ② 結合の `gap` を 0.3 秒へ下げる | 件数は増えるが上限が無いままなので、連続した発話では同じことが起きる |
| ③ `split_max_pause_sec` を上げる / 0 にする | カットしていない素材で「17 文字 76.8 秒」の退行が戻る。測り方が間違っているのであって、しきい値の問題ではない |
| ③ 出来上がったテロップを後から結合する | 隣接の判定を Timeline 側でやり直すことになり、単語と本文の対応 (`_item_from_words`) が崩れる。原因の場所で直す |
