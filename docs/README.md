# docs ドキュメント索引

このフォルダには **現行仕様を述べる文書**と、**その時点の記録 (履歴) である文書**の 2 種類がある。
両者を混ぜて読むと必ず矛盾する (古い決定が後の要望で覆されているため)。
読むときは次の優先順を守ること。

| 順位 | 対象 | 位置づけ |
|---|---|---|
| 1 | `src/` の実装 | **最終的な正** |
| 2 | `docs/design/design.md` | 現行設計書 (実装の要約) |
| 3 | `docs/howto/` / `docs/layout/` / `docs/HowToRelease.md` | 現行の利用者向け・画面・配布手順 |
| 4 | `docs/request/` `docs/error/` `docs/quality/` `docs/security/` `docs/reduce/` `docs/analyze/` | **履歴**。過去の意思決定の記録。現行仕様の根拠として単独で引用しない |

最終更新: 2026-11-06 (対象 v1.8.2)

## 2. 履歴文書の読み方

* ファイル名の規則は **`requestN.md` = 要望 / `resolveN.md` = それに対する設計書**。
  `error/<日付>/` は **`error.md` = 現象報告 / `resolve.md` = 原因と修正設計**。
* 履歴文書に書かれた設定値・既定値・モジュール名は**その時点のもの**であり、
  現在の値は `src/settings/settings_window.py` の `DEFAULT_SETTINGS` と
  `docs/design/design.md` を見ること。
* 履歴文書どうしで結論が食い違う場合、**日付とバージョンが新しい方が有効**である。
  代表的な反転は次のとおり。

| 項目 | 古い決定 | 現行 |
|---|---|---|
| GPU / CUDA | GPU 自動選択・CUDA ランタイム同梱 (ver1 resolve5) | **CPU 実行に統一・CUDA 非同梱** (ver1 resolve8) |
| 無音カット | 実カットして中間動画を作る | **編集点方式** (ver3 resolve。`silence_cut.mode=edit_points`) |
| 配布形態 | zip を解凍して exe を起動 | **インストーラ方式** (`StretheusSetup.exe` / ver1 resolve8) |
| 切り抜き候補数 | TOP5 (ver2 resolve17/18 の呼称) | `archive.scoring.top_n` = **10** |
| テロップの色 | 役割 (配信者/サブ/コメント) で決まる | **トラック単位の指定**を優先 (ver9 resolve13) |
| ぼかし | 人物を自動検出して追う (ver5 resolve2〜4) | **囲む → 追う → キーフレーム**へ単純化 (ver5 resolve8) |
| ポイント制 | クライアント側 SQLite で管理 | **サーバー (Stretheus API) が判定**。透かし要否も応答で決まる (ver5 resolve) |

## 4. 文書を追加・更新するときの決まり

1. 新しい要望は `docs/request/verN/requestM.md` に書き、設計書を `resolveM.md` として同じ場所に置く
   (`docs/CLAUDE.md`「実装前に設計を行うこと」)。
2. 実装が終わったら、**その内容が現行仕様に影響する場合は `docs/design/design.md` を更新する**。
   履歴文書だけを足して現行設計書を放置すると、本書が解消した矛盾が再発する。
3. 画面の見た目・操作が変わったら `docs/howto/` と `docs/layout/` を見直す。
4. 文書間の相互参照はリポジトリ相対パス (`docs/request/ver1/resolve8.md` のように
   **verN まで含める**) で書く。
5. 別リポジトリの文書を参照するときは `StretheusAPI docs/request/resolve2.md` のように
   リポジトリ名を前置し、本リポジトリのファイルと区別する。
