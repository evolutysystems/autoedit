## 1. 方針: 日本語の原文をキーにする

対訳表のキーは **日本語の原文そのもの**にした。

```python
label.setText(tr("設定"))            # ja → "設定" / en → "Settings"
```

* `tr()` は日本語のとき**引数をそのまま返す**。対訳表を一切見ないため、
  日本語表示の挙動は従来と 1 バイトも変わらない。訳の漏れや誤りが
  日本語利用者へ影響しない (§7 の例外方針と同じ考え方)。
* キーを別途作らないため、呼び出し側を読むだけで何が出るか分かる。
  キー名と文言が食い違う (= 画面を見ないと分からない) 事故が起きない。

### 1.1 Qt の翻訳機構 (.ts / .qm) を使わない理由

| | Qt (QTranslator) | 本方式 |
| --- | --- | --- |
| ビルド | `lupdate` / `lrelease` と `.qm` の同梱が要る | 不要 (純 Python モジュール) |
| 非 QObject から | `QCoreApplication.translate` が要る | `tr()` をそのまま呼べる |
| 配布 | `main.spec` の `datas` へ追加が要る | 通常の import で自動的に入る |

`pipeline` / `services` / `timeline` など QObject でないところにも画面へ出る
文言があり (進捗ラベル・例外メッセージ)、そこも同じ書き方で訳せるほうがよい。
同梱物を増やさない方針 (ライブラリを足さない) にも合う。

## 2. `src/i18n` の公開 API

本モジュールはプロジェクト内の他モジュールへ依存しない (標準ライブラリのみ)。
`settings_window` も `theme` も `pipeline` も、循環を気にせず import できる。

| 名前 | 役割 |
| --- | --- |
| `tr(text, /, **kwargs)` | 原文を現在の言語へ訳す。`kwargs` があれば `str.format` で差し込む |
| `language()` | 現在の言語コード (`"ja"` / `"en"`) |
| `set_language(code)` | 言語を切り替える。変わったときだけ `True` を返し、購読者へ通知する |
| `apply(settings)` | `setting.json` の `ui.language` を反映する (起動時に 1 度) |
| `normalize(code)` | 言語コードの正規化。未対応・未指定は `"ja"` へ倒す |
| `subscribe(cb)` / `unsubscribe(cb)` | 言語切替の通知の購読 / 解除 |
| `missing_keys()` | 対訳表に無かった原文の一覧 (訳し漏れの確認用) |
| `SUPPORTED_LANGUAGES` / `LANGUAGE_NAMES` | ドロップダウンに出す言語と表示名 |

### 2.1 差し込みは名前付きで行う

f-string は訳せないため、差し込みのある文言は名前付きプレースホルダへ直した。

```python
# 変更前
self.status_label.setText(f"完了: {output_path}")
# 変更後
self.status_label.setText(tr("完了: {path}", path=output_path))
```

語順は言語で変わるため、位置指定 (`{}`) は使わない。
`tr()` の第 1 引数は**位置専用** (`def tr(text, /, **kwargs)`) にしてある。
`tr("{text} / 次回リセット {reset}", text=…)` のように `text` という名前の
差し込みがあり、引数名と衝突するため。

## 3. 原文を直接 `tr()` へ渡さない箇所

文言が「呼び出し側のリテラル」で、訳すのは「中継役」という形がいくつかある。
どちらで訳すかは **言語切替に追随できるか** で決めた。

| 形 | 訳す場所 | 理由 |
| --- | --- | --- |
| モジュール定数 (`_DROP_PLACEHOLDER` など) | 使うところ | 定義時に訳すと起動時の言語で固定される |
| 項目名 (`_make_column_label("動画ディレクトリ")`) | ヘルパの中 | 呼び出しが 65 か所あり、1 か所で訳すほうが漏れない |
| 選択肢の表 (`_make_value_combo(ALIGNMENT_OPTIONS)`) | ヘルパの中 | 保存されるのは値のほうなので、表示だけ訳せばよい |
| 工程名 (`context.begin_step("無音カット")`) | `pipeline_context` | 進捗の文言を組み立てる 1 か所に集まっている |
| 取り消しの文言 (`Command.label`) | 表示する直前 | コマンド生成時に訳すと、切替後も古い言語で残る |

件数が入る `Command.label` (`字幕の編集（3 件）`) だけは組み立て時に訳す。
`tr()` は対訳表に無い文字列を素通しするため、表示直前にもう一度 `tr()` を
通しても二重に訳されることはない。

## 4. setting.json: `ui.language`

```jsonc
"ui": {
    "language": "ja",   // "ja" (既定) / "en"
    ...
}
```

* 既定は `"ja"`。更新インストールでも従来どおり日本語で立ち上がる。
* 実体の既定は `src/gui/theme.py` の `DEFAULT_UI_SETTINGS` が持つ
  (ui セクションの唯一の出どころ / ver3 resolve3 §4-2 に従う)。
* 未対応の綴り (`"fr"` など) や未指定は `i18n.normalize` が日本語へ倒す。
  `"en-US"` / `"EN"` のような手書きも先頭 2 文字で受け付ける。
* 既存の `_merge_with_defaults` がキーを補完するため、旧 setting.json でも
  次回起動時に `"language": "ja"` が書き足されるだけで済む (移行処理は不要)。

## 5. 切替 UI と、画面を作り直さない貼り替え

### 5.1 置き場所 (要望)

`QTabWidget` の**左上コーナー** (`Qt.TopLeftCorner`) へ `QComboBox` を置いた。
設定ボタンは右上コーナーにあり、コーナーウィジェットはどちらもタブバーと同じ帯に
入るため、**設定ボタンと同じ高さ**の左端になる。

```text
┌──────────────────────────────────────────────────────────────┐
│ [English ▼] │ クリップ用 │ アーカイブ切り抜き用 │  残高  サブスク  [⚙] │
├──────────────────────────────────────────────────────────────┤
```

右コーナーと同じ `theme.install_tab_corner` で包むため、下辺の余白もそろう。
高さは `showEvent` と テーマ貼り替え後に `_sync_language_combo_height()` で
設定ボタンへ合わせる。`_build_ui` の時点では QSS がまだ当たっておらず、
ボタンの `sizeHint` が本来より大きいため、表示後に測り直す必要がある。

### 5.2 ドロップダウンの表示名

| コード | 表示 |
| --- | --- |
| `ja` | 日本語 |
| `en` | English |

**どちらの言語を選んでいても両方この綴りで出す**。英語話者に「日本語」は読めず、
訳してしまうと自分の言語を見つけられなくなるため。

### 5.3 切替の流れ

```text
[ドロップダウンを変更]
   ↓
setting.json へ保存 (失敗しても表示だけは切り替える)
   ↓
theme.invalidate_cache()      ← テーマ側の設定キャッシュも language を持つため
   ↓
i18n.set_language(code)
   ↓
購読者 (MainWindow._retranslate) へ通知
   ↓
各画面の retranslate() … 文言だけ差し替える
```

**画面を作り直さないため、編集中の状態は一切失われない**
(選択中のファイル・Timeline の内容・選択・Undo 履歴・進捗)。
テーマの明暗切り替え (ver3 resolve3 §5.10-2) と同じ方針。

### 5.4 `retranslate()` を持つ画面

| 画面 | 方法 |
| --- | --- |
| `MainWindow` | タブ名・設定/サブスクのボタン・ドロップダウンの補足 |
| `ClipTabWidget` | D&D の案内文・各ボタン。実行中はステータスを触らない |
| `ArchiveTabWidget` | 説明文・各ボタン。ログイン状態は専用の経路へ任せる |
| `ProjectResumeRow` | 見出しとボタン。コンボは `refresh()` が作り直す |
| `PointsIndicator` | 最後に表示した残高で組み立て直す (通信しない) |
| `SubscriptionWindow` | 静的なラベルを入れ替えて `_apply_state()` を呼び直す |
| `AccountTab` | 見出し・ボタン・表の見出し。残高と履歴は次の「更新」に任せる |
| `SettingsWindow` | §5.5 |

その場で開いていないダイアログ (Timeline 編集・ぼかし・字幕編集など) は、
**次に開いたときに新しい言語で作られる**ため、何もしなくてよい。

### 5.5 設定画面だけはタブを作り直す

設定画面は項目名・注記・選択肢が画面じゅうに散っており、1 つずつ `setText` し直すと
取りこぼしやすい。そこで**タブの中身を作り直す**。

* 入力途中の値は `_collect_settings()` で控え、`_load_to_ui(pending)` で戻すため
  **保存していない編集も失われない**。
* 「アカウント」タブだけは作り直さない。作り直すと残高と履歴を取り直す
  (= 通信が走る) ため、文言の貼り替えだけを頼む。
* `_load_to_ui` に引数 `source` を足した (省略時は従来どおり setting.json を読む)。
  既存の呼び出しは引数なしのまま動く。

## 6. 英語で項目名が切れる問題

設定画面の項目名は `COLUMN_LABEL_WIDTH = 100` を**最小幅**として置いていた。
画面の幅が足りないと列は最小幅まで縮むため、日本語より長い英語の項目名
(`Background / shadow colour` = 153px など) が途中で切れた。

`_make_column_label` の下限を「設定の最小幅」と「文言そのものの幅」の
**大きいほう**にした。列が文言より狭くならないため、どの言語でも切れない。
必要なぶんだけウィンドウが広がるので、`WINDOW_WIDTH` の調整は要らない。

## 7. 例外方針

**訳の不具合でアプリを止めない**。i18n の経路はすべて失敗しても素通しする。

| 起きたこと | 振る舞い |
| --- | --- |
| 対訳表にキーが無い | 原文 (日本語) のまま表示し、ログへ 1 度だけ記録する |
| 差し込みの名前が原文と対訳で食い違う | 原文側で差し込みを試し、それも駄目なら訳文をそのまま返す |
| `retranslate()` が例外を投げた | その画面だけ飛ばし、他の画面の貼り替えは続ける |
| setting.json へ保存できない | 表示だけ切り替える (次回起動で戻るだけ) |

## 8. 対訳表の増やし方

1. 画面へ出る文言を `tr("…")` でくるむ。
2. `src/i18n/catalog_en.py` の `CATALOG` へ `"原文": "English"` を足す。
3. `python -m unittest tests.test_i18n` を実行する。

`tests/test_i18n.py` が次を検査するため、足し忘れはテストで落ちる。

* `src` 内の `tr("…")` の原文が対訳表にそろっていること
* 差し込み (`{name}`) の名前が原文と対訳で一致していること
* 英訳に日本語が残っていないこと / 訳が空でないこと

**原文を変えるときは対訳表のキーも必ず同時に直す**。
1 文字でも違うと引けず、英語のときだけ日本語に戻る。

## 10. テスト

* 日本語では `tr()` が原文をそのまま返すこと (従来の挙動を変えない)
* 英語では対訳表を引き、無いキーは原文へ落ちること
* 差し込みが名前付きで効くこと / 失敗しても例外を投げないこと
* 言語コードの正規化 (`en-US` / `fr` / `None` など)

### 10.1 実機での確認 (2026-10-08)

* メイン画面・設定画面の全タブについて、英語表示にしたとき画面上の文言に
  日本語が残っていないことを確認した。残るのは **利用者のデータ**

* 言語を切り替えても、設定画面の入力途中の値が失われないことを確認した。
* 日本語表示の見た目が従来と変わらないことを確認した。

## 11. 残件

* 日本語・英語以外を足すときは `src/i18n/catalog_<code>.py` を作り、
  `i18n._CATALOGS` と `SUPPORTED_LANGUAGES` / `LANGUAGE_NAMES` へ足す。
  ドロップダウンは `SUPPORTED_LANGUAGES` を見て並べるため、UI の変更は要らない。
* 起動時に OS の表示言語へ自動で合わせる案は**入れていない**。
  既存利用者が更新後にいきなり英語になるのを避けるため、既定は `"ja"` に固定した。
  入れるなら `ui.language` に `"auto"` を足し、`normalize` で解決する形になる。
