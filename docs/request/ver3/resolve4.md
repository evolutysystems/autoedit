#### Q3 の解釈について

回答時点の「クリップ用」は**設定ボタンと実行ボタンが横に 2 つ並んだ状態**でしたが、
M3 で設定ボタンがタブ外へ出るため、実行ボタンは列に 1 つだけ残ります。
`QPushButton` は `QHBoxLayout` の中で横に伸びるため、**放置すると実行ボタンが横幅いっぱいに広がり**、
Q3 で懸念された「間延び」がクリップ用側でも起きます。

そこで **「クリップ用と同じ」を「両タブの主要動作ボタンを同一の見た目・同一の幅にする」** と解釈し、
実行ボタンと採点開始ボタンの**双方**へ同じ幅を与えます（§5.10）。
これにより 2 つのタブを行き来しても主要動作ボタンの位置と大きさが変わりません。

### 1.2 E5 は resolve3 の R10 を意図的に変更する

resolve3 の **R10**（回答 Q3）では「Timeline はクリップも含め現状の見た目を維持する」と確定し、
`_paint_clip` には手を入れない方針でした。E5 はこれを**利用者の指示で明示的に変更**するものです。

本書では R10 を次のように読み替えます。

> **R10'** … Timeline のクリップは**色・角丸・半透明化を変更しない**。
> ただし**アウトラインの太さのみ**調整する（編集点の判別しやすさを高める方向のため、
> R10 の目的である「編集点の境界が判別できること」とは矛盾しない）。

## 2. 現状分析（実測）

### 2.1 E2 / E4 の原因 ── resolve3 で入れた QSS の余白

**これは調整要望ではなく、resolve3 が持ち込んだ不具合です。**

resolve3 §5.3 で全ボタンへ次の QSS を当てました（`theme.py:629`）。

```css
QPushButton {
    border: {border.width} solid {glass.border};   /* 左右 1px ずつ */
    padding: 6px 14px;                             /* 左右 14px ずつ */
}
```

横方向に **14×2 + 1×2 = 30px** の余白が付きます。
ところが各アイコンボタンの `setFixedWidth()` は **QSS 導入前**（素の Qt ボタンは左右の余白が数 px）に
決めた値のままなので、記号を描く領域が足りず見切れます。

実測値（本テーマ適用下・`sizeHint()` が必要幅）:

| ボタン | 位置 | 現在の固定幅 | 必要幅 | **不足** |
|---|---|---|---|---|
| ⏮ | `preview_panel.py:223` | 32 | 42 | **10px** |
| ◀◀ | `preview_panel.py:230` | 40 | 54 | **14px** |
| ▶ | `preview_panel.py:237` | 36 | 42 | **6px** |
| ▶▶ | `preview_panel.py:244` | 40 | 54 | **14px** |
| ⏭ | `preview_panel.py:251` | 32 | 42 | **10px** |
| 🔊 | `preview_panel.py:276` | 32 | 42 | **10px**（要望外だが同因） |
| － | `timeline_view.py:798` | 32 | 42 | **10px** |
| ＋ | `timeline_view.py:802` | 32 | 42 | **10px** |
| 全体 | `timeline_view.py:806` | 指定なし | 54 | 0（見切れない） |

> 記号そのものの幅は **12px**（余白を外して実測）。つまり幅の大半を QSS の余白が占めています。

### 2.2 同じ原因が別の場所でも効いている

余白 30px は**アイコン主体の小さなボタンすべて**を膨らませています。

| 箇所 | 意図した幅 | 実際の `sizeHint()` |
|---|---|---|
| 設定画面の色見本ボタン（`settings_window.py:1448`） | `min-width: 28px` | **78px** |
| アイコンのみのボタン（18px アイコン） | 〜28px | **48px 必要** |

色見本が意図の約 2.8 倍に膨らんでいることは、**S2（カラー 3 列の横並び）の幅を圧迫する**ため
本件と無関係ではありません（§5.6）。

**したがって E2・E4・S2・M3 は「アイコンボタンの余白」という単一の原因を共有します。**

### 2.3 タブペインの角丸（M1 / S1）

`theme.py:685` で全 `QTabWidget` のペインに `border-radius: {radius.panel}`（既定 16px）を当てています。
タブバーは左端（x=0）から始まるため、**先頭タブが選択されているとき**だけ、
選択タブの塗りとペインの丸い左上角のあいだに切れ込みが見え、両者が繋がって見えません。

* メイン画面の先頭タブ = **クリップ用**（`main_window.py:696`）
* 設定画面の先頭タブ = **一般**（`settings_window.py:803`）

M1 と S1 は**同一の現象**であり、同一の仕組みで解決できます。

### 2.4 設定ボタンの所在（M3）

現在、設定ボタンは `ClipTabWidget._build_ui()` 内にあります（`main_window.py:444`）。

* 実体・ハンドラ・`SettingsWindow` の参照保持がすべて `ClipTabWidget` 側にある
  （`_on_open_settings` = `:498` / `_settings_window` = `:418`）
* このためクリップ用タブを選んでいる間しか設定を開けない ← 要望どおりの問題

### 2.5 カラー入力欄の現状（S2 / S3）

**同じ構造の 3 行組が 2 グループ**あり、どちらも「字幕」タブの中で縦に並んでいます。

| グループ | 位置 | 値の書式 | `with_alpha` |
|---|---|---|---|
| テロップカラー（S2） | `settings_window.py:966`〜`:985` | HTML `#RRGGBB` | `False` |
| アウトラインカラー（S3） | `settings_window.py:1045`〜`:1065` | ASS `&HAABBGGRR` | `True` |

各行は「ラベル列」＋「`_make_color_picker()` が返す 横 1 列（入力欄＋色見本）」で、
**2 グループとも同じヘルパを使っている**ため、横並び化も共通の処理で行えます（§5.6-3）。

設定画面の幅の実測:

| 項目 | 値 |
|---|---|
| `WINDOW_WIDTH`（`resize()` の要求値） | 300 |
| **実際の最小幅**（他タブの内容で決まる） | **672px** |
| `INPUT_FIELD_MIN_WIDTH` | 160 |
| `COLUMN_LABEL_WIDTH` | 100 |

**要求値 300 は最小幅 672 に負けて効いていません。**
つまり画面は実際には 672px あり、横 3 列にする余地があります（§5.6 で試算）。

## 3. 方式選定

### 3-1. 「先頭タブ選択時だけ左上を角丸にしない」をどう実現するか（M1 / S1）

QSS の `QTabWidget::pane` には「どのタブが選択されているか」を表す状態がありません。

| 方式 | 内容 | 評価 |
|---|---|---|
| A. 常に左上を角丸にしない | `border-top-left-radius: 0` を固定 | **不採用**。要望は「選択時だけ」 |
| B. **動的プロパティ + QSS の属性セレクタ** | `currentChanged` でプロパティを更新し `unpolish/polish` で再評価 | **採用** |
| C. `paintEvent` を自前実装 | ペインを自分で描く | 過剰。QSS 管理から外れる |

**採用: B。** 実機（PySide6 6.11.0 / offscreen）で**動作を確認済み**です。

```python
qss = """
QTabWidget::pane { border-radius: 16px; }
QTabWidget[firstTabSelected="true"]::pane { border-top-left-radius: 0px; }
"""
```

検証結果（ペイン左上端の画素を採取）:

| 選択タブ | プロパティ | 左上端の画素 | 意味 |
|---|---|---|---|
| 先頭（index 0） | `True` | ペインの塗り | **角が四角い（意図どおり）** |
| 2 番目 | `False` | ウィンドウ背景 | 角が丸く抜けている（従来どおり） |

M1 と S1 は同じ仕組みなので、**`theme.py` に共通ヘルパを 1 つ置いて両画面から呼びます**
（デザインの一元管理 / resolve3 §4-2）。

### 3-2. アイコンボタンの見切れをどう直すか（E2 / E4）

| 方式 | 内容 | 評価 |
|---|---|---|
| A. **固定幅を必要幅まで広げる** | `setFixedWidth` の値を上げる | **採用（主）**。要望の文言「ボタンの幅を増やしたい」そのもの |
| B. **アイコン専用の QSS で余白を減らす** | `#iconButton { padding: 6px 6px; }` | **採用（併用）**。原因側の是正。狭い場所（コーナー・色見本）に効く |
| C. `setFixedWidth` をやめて `sizeHint` 任せ | 幅が揃わず並びが乱れる | 不採用 |

**採用: A を主とし、B を併用する。**

A だけでも見切れは直りますが、B を併用する理由は 2 つあります。

1. **同じ原因の他の箇所（色見本 78px・コーナーボタン）も一緒に直る**（§2.2）
2. アイコンに 14px の左右余白は元々過剰で、**原因を放置したまま幅だけ広げると
   ボタンが不必要に大きくなる**

なお **B だけで済ませない**のは、要望が明確に「幅を増やしたい」と述べているためです。
B で余白を詰めたうえで、A で見やすい幅を明示的に与えます。

### 3-3. 幅・太さの値をどこに置くか

`docs/CLAUDE.md`「ハードコードは禁止し、設定可能な値は `setting.json` で管理する」に従います。

| 方式 | 評価 |
|---|---|
| A. `setFixedWidth(44)` のように直書き | **不可**。現状もそうなっているが、本件で触るなら是正する |
| B. **`setting.json`（`timeline` セクション）へ追加** | **採用**。`track_height_px` / `header_width_px` など**既存の寸法値と同じ置き場**がある |

**採用: B。** 各ウィジェットが既に読んでいる区画へ足します（§6）。

* トランスポート = `timeline.preview`（`preview_panel` が読む区画）
* ズーム・アウトライン = `timeline.ui`（`timeline_view` が読む区画）

### 3-4. 設定ボタンをタブ外へ出す方法（M3）

| 方式 | 内容 | 評価 |
|---|---|---|
| A. **`QTabWidget.setCornerWidget(w, Qt.TopRightCorner)`** | タブバーの右端へ載せる | **採用**。タブの高さに収まり、レイアウトを増やさない |
| B. タブの上に別の `QHBoxLayout` を積む | 縦方向を消費し、タブとの一体感が無くなる | 不採用 |

**採用: A。** 実機で配置・表示を確認済みです。

ただし**コーナーの高さはタブバー（実測 28px）に制限される**ため、
現在の余白のままだと 18px のアイコンに必要な幅が 48px になります。
§3-2 B のアイコン用 QSS を当てて収めます。

### 3-5. 「採点開始」をアイコン化する方法（M2）

クリップ用の実行ボタンは `_glyph_icon()`（`main_window.py:93`）で
Unicode 記号を `QPixmap` へ描いて `QIcon` 化しています（画像素材を増やさない方針）。

**この関数は `main_window.py` にあり、`archive_tab.py` からは使えません。**
`main_window` が `archive_tab` を import しているため、逆向きの import は循環します。

| 方式 | 評価 |
|---|---|
| A. `archive_tab.py` へ関数を複製 | 二重管理。テーマ追随も二重に書くことになる |
| B. **`theme.py` へ `glyph_icon()` として移す** | **採用**。両画面が既に `theme` を import 済みで循環しない。アイコン色はテーマから引くので置き場としても自然 |
| C. 新規モジュール `gui/icons.py` | 妥当だがファイルを増やす。B で足りる |

**採用: B。** `main_window._glyph_icon` は `theme.glyph_icon` を呼ぶだけの薄い委譲として残し、
既存の呼び出し 2 か所（`:488` / `:489`）を壊しません。

### 3-6. E5（アウトラインを太く）で注意が要る点

`QPainter.drawRect()` のペンは**矩形の境界線を中心に**描かれます。
太さ N のペンは境界の**外側へ N/2 はみ出します**。

```
太さ 1px           太さ 2px            太さ 3px
│▒▒▒▒│           ░│▒▒▒▒│░           ░│▒▒▒▒│░
 はみ出し 0        外へ 0.5px          外へ 1px
```

クリップは時間軸上で隣と接して並ぶため、**太くすると隣のクリップへ食い込みます**。
「編集点の境界が判別できること」（resolve3 §3-4）を損なわないよう、
**太さを増やしたぶん矩形を内側へ縮める**（`rect.adjusted()`）ことを設計に含めます（§5.9）。

また `_paint_clip` は**長尺で 1,000 個超**呼ばれるため、描画コストの実測を完了条件に置きます（§10）。

## 4. 設計方針

1. **見た目だけを変える。** レイアウトの意味・シグナル配線・編集ロジックには触れない。
   出力される動画・ASS・FCPXML は現状と同一（§8）。
2. **原因を直す。** E2 / E4 は resolve3 が持ち込んだ余白が原因なので、
   幅を広げるだけでなく**アイコンボタンの余白そのものを是正**する（§3-2）。
3. **スタイルは `theme.py` に集約する。** 角丸の切り替えもアイコン生成も
   個別画面へ QSS を書かず、`theme.py` のヘルパ経由にする（resolve3 §4-2 を維持）。
4. **ハードコードしない。** 追加する幅・太さは `setting.json` から変更できる（§6）。
5. **いつでも戻せる。** `ui.theme = "system"` で従来の Qt 既定へ戻る性質を壊さない。
6. **可読性・判別しやすさは装飾より優先する。**（resolve3 §3-4 を継承）
7. **重くしない。** E5 は 1,000 個超のクリップに効くため、描画コストを実測する。

### 5.2 タブペインの角丸切り替え（M1 / S1）

`theme.py` へ QSS 1 行とヘルパ 1 つを足します。

```css
/* 先頭タブが選ばれている間だけ、ペインの左上を角丸にしない (resolve4 M1 / S1)。

QTabWidget[firstTabSelected="true"]::pane { border-top-left-radius: 0px; }
```

```python
# 先頭タブ選択時にペイン左上の角丸を外す (resolve4 M1 / S1)
# QSS には「どのタブが選択中か」を表す状態が無いため、動的プロパティで橋渡しする。
# 取り付けた時点の選択状態も反映するので、呼ぶだけでよい。
def bind_tab_pane_corner(tab_widget):
    def sync(index):
        tab_widget.setProperty("firstTabSelected", index == 0)
        # プロパティの変更は自動では QSS へ反映されないため再評価させる
        tab_widget.style().unpolish(tab_widget)
        tab_widget.style().polish(tab_widget)
        tab_widget.update()

    tab_widget.currentChanged.connect(sync)
    sync(tab_widget.currentIndex())
```

呼び出しは 2 か所だけです。

| 画面 | 呼び出し位置 |
|---|---|
| メイン | `main_window.py:693` 付近（`self.tabs` 生成直後） |
| 設定 | `settings_window.py:802` 付近（`tabs` 生成直後） |

> **左上のみ**である点に注意します。右上・左下・右下は従来どおり丸いままです。
> タブが右端まで伸びているわけではないため、右上を角丸のままにしても違和感は出ません。

#### 5.2-1 他タブ選択時は角丸へ戻す（回答 Q6）

角丸を外すのは**先頭タブを選んでいる間だけ**で、他のタブへ切り替えたら
**左上も角丸に戻る**ことが要件です。

上記の `sync()` は `index == 0` の真偽をそのままプロパティへ入れるため、
先頭以外を選んだ時点で `firstTabSelected = False` となり QSS の追加ルールが外れます。
**片道の処理にはなっていません。**

| 操作 | プロパティ | 左上の角 |
|---|---|---|
| 起動直後（先頭タブ） | `True` | 四角 |
| 2 番目のタブへ切り替え | `False` | **角丸へ戻る** |
| 先頭タブへ戻す | `True` | 再び四角 |

`unpolish/polish` を**毎回両方向で呼ぶ**ことが肝心で、
片方向だけだと QSS が再評価されず角丸が戻りません。
**往復して元に戻ること**を §10 段 2 の完了条件に含めます。

#### 5.7-4 実行中は押せないようにする（回答 Q1）

設定ボタンがタブの外へ出ると、**どのタブが実行中でも同じ 1 つのボタン**を制御することになります。

現状、実行中の状態はタブごとに閉じています。

| タブ | 実行状態を切り替える処理 | 無効化している要素 |
|---|---|---|
| クリップ用 | `ClipTabWidget._set_running()`（`main_window.py:600`） | 実行・参照・入力欄 |
| アーカイブ切り抜き用 | `ArchiveTabWidget._set_running()`（`archive_tab.py:520`） | 採点開始・参照・入力欄・ログイン ほか |

**どちらのタブが実行中でも設定ボタンを無効化する**必要があるため、
各タブから実行状態を通知し、`MainWindow` 側で集約します。

| 方式 | 内容 | 評価 |
|---|---|---|
| A. `MainWindow` が各タブの worker を直接見る | タブの内部実装へ踏み込む | 不採用。結合が強くなる |
| B. **各タブが `running_changed` シグナルを出す** | 既存の `_set_running()` の末尾で `emit` するだけ | **採用**。1 行の追加で済み、タブの独立性を保てる |

```python
# 実行状態の変化を親へ通知する (resolve4 §5.7-4 / 回答 Q1)
# タブ外の設定ボタンを無効化するために使う。タブ自身の無効化処理は従来どおり。
running_changed = Signal(bool)
```

```python
# MainWindow 側: どちらかのタブが実行中なら設定ボタンを無効化する
def _on_tab_running_changed(self, tab_key, running):
    if running:
        self._running_tabs.add(tab_key)
    else:
        self._running_tabs.discard(tab_key)
    self.settings_button.setEnabled(not self._running_tabs)
```

**タブごとの真偽をまとめて持つ**（`_running_tabs`）のは、
一方のタブが終了したときにもう一方がまだ実行中なら
**有効化してはいけない**ためです。単純な `bool` 1 個だと取りこぼします。

> **設定画面が既に開いているときの扱い**: 実行中に**新しく開けなくする**だけで、
> 既に開いている `SettingsWindow` を閉じたりはしません。
> 実行中に設定を変更しても、パイプラインは開始時に読み込んだ設定で動き続けます
> （`ClipTabWidget._on_run` が実行開始時に `load_settings()` する既存挙動 / `:560`）。

### 5.9 クリップのアウトラインを太くする（E5 / R10'）

#### 5.9-1 太さ

| 状態 | 現在 | 変更後 | 設定キー |
|---|---|---|---|
| 通常 | 1px | **2px** | `timeline.ui.clip_outline_width_px` |

#### 5.9-2 隣への食い込みを防ぐ（§3-6）

太さ N のペンは境界から外へ N/2 はみ出すため、**矩形を内側へ縮めて**描きます。

```python
# アウトラインは境界線を中心に描かれ、太さのぶん外側へはみ出す。
# 隣のクリップへ食い込むと編集点の境界が読めなくなるため、
# 太さに応じて矩形を内側へ縮めてから描く (resolve4 §3-6)。
inset = width // 2
outline_rect = rect.adjusted(inset, inset, -inset, -inset)
painter.setPen(QPen(outline_color, width))
painter.drawRect(outline_rect)
```

これにより**アウトラインは常にクリップの内側**に収まり、クリップの占有幅は現在と同じままです。

#### 5.9-3 極端に細いクリップへの配慮

`rect` の幅は `max(int(x2 - x1), 2)` で最小 2px です（`:372`）。
3px のアウトラインを 2px 幅の矩形へ描くと**塗りが見えなくなります**。

**矩形の短辺より太い場合は太さを落とす**ことで、細いクリップでも種別色が残るようにします。

```python
# 細いクリップでは塗りが潰れないよう太さを抑える
width = min(width, max(1, min(rect.width(), rect.height()) // 2))
```

採点開始ボタンは `primaryButton`（アクセント塗り）なので、
resolve3 §5.2-1 の `accent.on`（塗りの上で読める色を自動選択）を使います。
クリップ用の実行ボタンが `refresh_theme()` で行っている処理と同じです。

**アーカイブ用タブにも `refresh_theme()` を用意**し、
`MainWindow._on_theme_changed` から呼びます（OS の明暗が変わったときにアイコンが追随するため）。

> これを忘れると、テーマ貼り替え後に採点開始のアイコンだけ**前のモードの色のまま**残ります。
> クリップ用は resolve3 で対応済みで、アーカイブ用は今回アイコン化して初めて必要になります。

## 6. setting.json 追加案（追加のみ・既存キー不変）

```jsonc
{
  "timeline": {
    "ui": {
      // …既存キーは変更しない…
      "zoom_button_width_px": 40,             // Timeline 左下のズームボタン (E4)
      "clip_outline_width_px": 2,             // クリップのアウトライン (E5)
      "clip_outline_selected_width_px": 3     // 選択中クリップのアウトライン (E5)
    },
    "preview": {
      // …既存キーは変更しない…
      "transport_button_width_px": 40,        // ⏮ ▶ ⏭ 🔊 (E2)
      "transport_wide_button_width_px": 52,   // ◀◀ ▶▶ (2 記号ぶん広い / E2)
      "transport_row_right_margin_px": 8      // 「高精度プレビュー」の右余白 (E3)
    }
  }
}
```

* `DEFAULT_SETTINGS`（`settings_window.py`）へ同内容を追加します。
* `timeline` の入れ子は既存の `_fill_timeline_nested_defaults()` が欠落キーを補完するため、
  **既存ユーザーの `setting.json` にも自動で現れます**（追加実装は不要）。
* **`src/timeline/builder.py` の `timeline_config()` にも追加が必要です**（実装時に判明）。
  Timeline 系ウィジェットが読む `controller.cfg` は `setting.json` を直接見るのではなく、
  この関数が**キーを 1 つずつ明示的に写して型と既定値を与える**構造になっています。
  ここへ追加しないと `KeyError` になり、`setting.json` 側だけの追加では効きません。
  0 以下を弾く `_positive_int()` を新設し、寸法の不正値は既定へ寄せます（§7）。
* **`ui` セクション（resolve3）へは追加しません。** 上記はいずれも Timeline 編集画面の
  寸法であり、テーマ（配色・ガラス）ではないためです。
### 6.1 モジュール定数として置くもの（`setting.json` には出さない）

次の 2 つは**画面レイアウトの内部寸法**であり、利用者が調整する性質のものではないため、
既存の `INPUT_FIELD_MIN_WIDTH` / `COLUMN_LABEL_WIDTH` と同じくモジュール定数とします。

| 定数 | 置き場 | 値 | 用途 |
|---|---|---|---|
| `COLOR_FIELD_MIN_WIDTH` | `settings_window.py` | 104 | テロップカラー欄（§5.6-1） |
| `OUTLINE_COLOR_FIELD_MIN_WIDTH` | `settings_window.py` | 140 | アウトラインカラー欄（§5.6-1） |
| `PRIMARY_ACTION_BUTTON_WIDTH_PX` | **`theme.py`** | 96 | 実行 / 採点開始（§5.10-2） |

> `PRIMARY_ACTION_BUTTON_WIDTH_PX` だけ `theme.py` へ置くのは、
> **両タブで同じ値を使う必要がある**一方、`archive_tab` から `main_window` は
> import できない（循環する / §3-5）ためです。
> `theme.py` には既に形状トークン（`SHAPE` の角丸・境界線幅）があり、
> `glyph_icon()` も同じ理由でここへ移すため、置き場として一貫します。
> 両ファイルとも既に `theme` を import 済みで、追加の依存は生じません。

## 7. エラー処理・フォールバック方針

| 事象 | 挙動 |
|---|---|
| `ui.theme = "system"` | QSS を当てないため角丸・余白の調整は効かない。**幅と余白（Python 側の値）は効く**ので見切れは起きない |
| 追加した寸法キーが欠落 | `_fill_timeline_nested_defaults()` が既定で補完する（§6） |
| 寸法キーが不正値（負・非数値） | 既定値へ戻して WARNING。描画は継続する |
| `bind_tab_pane_corner()` が例外 | 角丸は従来どおり（全角丸）のまま。**タブの動作は妨げない**（`try` で囲む） |
| `setCornerWidget` が効かない環境 | 設定ボタンが出ないと**設定画面を開けなくなる**ため、§9.2-Q2 のとおり実機で要確認 |
| 実行中に設定ボタンが無効化されたまま戻らない | 例外で `_set_running(False)` が呼ばれない場合に起こり得る。既存の `finished_ok` / `failed` / `cancelled` すべてが `_set_running(False)` を通ることを段 7 で確認する |
| クリップ幅が極小 | アウトラインの太さを自動で落とす（§5.9-3） |

**原則**: resolve3 §7 を継承し、見た目の不具合でアプリが操作できない状態を作らないこと。
