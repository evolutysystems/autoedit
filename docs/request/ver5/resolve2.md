## 2. 現状分析

### 2.1 「セクション」の実体は 2 種類ある

要望の「Timeline 上の全てのセクション」は、経路によって指すものが違う。

| 経路 | セクションの実体 | 素材 | 根拠 |
| --- | --- | --- | --- |
| クリップ用 | 無音カットで残った区間 = **V1 のベースクリップ 1 件**。すべて同じ 1 本の素材を指す | 正規化済みの本編 1 本 (`source.media_path`) | `timeline_builder.build` / `model.Timeline.base_clips` |
| アーカイブ用 | 採点で選ばれた **clip{N}** (= `source.archive.clips[]` の 1 件)。1 セクションが複数のベースクリップに分かれる | **セクションごとに別ファイル** (`prepared[].normalized_path`) | `archive/timeline_builder.py:401 archive_section` / `clip_writer._prepare_clips` |

つまり「全セクションへ反映する」は、

* クリップ用 = **1 本の素材の中の、離れた複数区間**へ反映する
* アーカイブ用 = **複数の素材ファイルにまたがって**反映する

の両方を満たす必要がある。後者があるため、同一人物の判定は
「同じ動画ファイルの中でトラッキングが途切れないこと」に頼れない (§3.2)。

### 2.2 レンダリングの合流点は `renderer.render` の 1 か所

Timeline モードの出力は、クリップ用・アーカイブ用のどちらも
`src/timeline/renderer.py:40 render()` を通る。

```text
クリップ用     pipeline_runner._run_timeline  → renderer.render(timeline, context)      → output_writer.run
アーカイブ用   clip_writer._render_clips      → renderer.render(sub_timeline, context)  → 結合
                 (archive/timeline_builder.py:250 split_by_clip がセクション単位へ分割)
```

したがって **ぼかしを `renderer.render` の中へ入れれば、両方の経路を 1 つの実装で覆える**。
レガシーモード (`silence_cut.mode != "edit_points"`) は Timeline 画面そのものが無く、
要望の前提 (R4) を満たさないため**対象外**とする (§9-6)。

### 2.3 焼き込みの差し込み口は 3 分岐 — watermark と同じ構造

`renderer.py:410 _render_overlays_and_subtitles` は次の 3 通りに分かれる。

| 分岐 | 条件 | 実装 |
| --- | --- | --- |
| そのまま返す | オーバーレイも字幕も無い | — |
| `_burn_subtitles_only` (`:449`) | 字幕のみ | `subtitle_generator.burn_subtitle` |
| `_composite` (`:486`) | オーバーレイあり | `filter_complex` を鎖状に組む |

ぼかしは**ベース映像に対して、字幕やオーバーレイを載せる前に**かける必要がある (R8)。
上の 3 分岐はいずれも「ベース映像 (`base_path`) を受け取る」点が共通しているため、
**ベース映像を受け取った直後が唯一の差し込み口**になる。

さらに `src/modules/comment_decor.py:312 build_icon_chains` が、
**`movie=` フィルタソースで外部素材を読み込み、`-i` を増やさずにチェーンへ混ぜる**前例を作っている。

```text
movie='<path>',format=rgba,scale=…[cic0];
[in][cic0]overlay=…[out]
```

この手口をそのまま使えば、ぼかし用のマスク動画も**入力本数を増やさずに**差し込める。
`_burn_subtitles_only` は `burn_subtitle(..., extra_chains=…)` を持っており、
`_composite` はチェーン配列を自前で組んでいるため、**どちらへも同じ文字列を足すだけ**で済む。

### 2.4 同梱済みの依存関係 — 検出器はライブラリを追加せずに動かせる

`src/` の実コードが import しているサードパーティは **PySide6 のみ**
(残りは標準ライブラリ。`faster-whisper` / `budoux` / `av` は遅延 import の任意依存)。
一方、凍結配布 (`src/dist/Stretheus/_internal/`) には既に次が入っている。

| パッケージ | 版 | 備考 |
| --- | --- | --- |
| `onnxruntime` | 1.24.4 | **ONNX モデルの推論に使える** |
| `numpy` | 2.4.4 | 行列演算・相関計算 |
| `PIL` (Pillow) | 12.3.0 | マスク画像の描画・ぼかし |
| `av` (PyAV) | 17.0.0 | プロセス内デコード/エンコード (`frame_source.py` が既に使用) |
| `torch` / `transformers` / `scipy` / `sklearn` | — | 他機能の依存で同梱済み |

開発環境でも `onnxruntime 1.24.4` / `numpy 2.4.4` が import できることを確認した。
**よって R10 を守ったまま、ONNX の検出モデルを回せる。** 追加で必要になるのは
Python パッケージではなく**モデルファイル (.onnx) だけ**である (§3.7)。

任意依存の作法は `subtitle_generator.py:370` の faster-whisper が前例になる
(関数の中で import し、失敗したら分かりやすい例外にする)。同じ書き方を踏襲する。

### 2.5 座標系は 3 つあり、変換を 1 か所へ閉じ込める必要がある

| 座標系 | 使う場所 | 範囲 |
| --- | --- | --- |
| 素材ピクセル | 検出結果 (素材の解像度) | 0〜素材幅 |
| キャンバスピクセル | レンダリング / プレビューの `QGraphicsScene` | 0〜`timeline.width` |
| 正規化座標 | `model.Transform` (中心原点 −1.0〜1.0) | −1〜1 |

素材 → キャンバスの変換は `renderer.py:283 _video_filters` の正規化チェーンで決まる。

```text
scale=W:H:force_original_aspect_ratio=decrease, pad=W:H:(ow-iw)/2:(oh-ih)/2
```

= **等倍率の縮小 + 中央寄せのレターボックス**。素材とキャンバスの規格が一致する場合
(`media_probe.needs_normalize` が False) は恒等変換になる。縦動画 (`vertical`) では
1080x1920 キャンバスに対してこの変換が効くため、**変換を無視すると縦動画でぼかし位置がずれる**。

### 2.6 Undo と永続化の器は `timeline.source` にある

* `commands.py:95 _snapshot` は `copy.deepcopy(timeline.source)` を控える。
  → **`source` へ入れた値は Undo/Redo が自動で効く**(アーカイブ用のテーマが既にこの仕組みを使っている)。
* `project_io.py:158 _source_to_dict` は `dict(source)` をそのまま書き出す。
  → **`source` へ入れた値はプロジェクト JSON へ自動で保存され、開き直しても残る**。
* ただし `_snapshot` は編集のたびに deepcopy する。**重いデータを `source` へ置いてはいけない。**

### 2.7 無い物

* 物体検出・追跡のコードは 1 行も無い (`grep` で 0 件)。
* OpenCV は開発環境にも配布物にも入っていない。**画像処理は numpy + PIL で行う。**
* `boxblur` / `gblur` は既に使っている (`clip_writer.py:209` のイントロカード)。FFmpeg 側の準備は要らない。
* モデルファイルの置き場 (`src/models/` 等) は無い。`main.spec` の `datas` は
  `comment_icon.png` と BudouX のデータのみで、**`watermark.png` すら入っていない**
  (ver5 resolve §8-3 の積み残し)。モデルを同梱するなら同じ場所を直す必要がある。

### 2.8 落とし穴 — アーカイブ用の分割は `source` を引き継がない

`archive/timeline_builder.py:275 _build_group_timeline` は、セクションごとの
サブ Timeline を新しく組み直すが、**`sub.source` を設定していない** (空のまま)。

```python
sub = Timeline(fps=…, width=…, height=…, orientation=…, zoom_px_per_sec=…)
sub.media_pool = list(timeline.media_pool)   # メディアは共有する
# ← source は引き継がれない
```

したがって §2.6 の方針 (指定を `source` へ持つ) をそのまま採ると、
**アーカイブ用の書き出しだけぼかしが消える。** ここに 1 行足すことを §5.5 で明示する。
メディアプールは参照を共有しているため、**`media_id` はサブ Timeline でもそのまま通じる**。

## 3. 方式選定

### 3.1 人物の検出

| 案 | 内容 | 追加ライブラリ | 精度 | 判定 |
| --- | --- | --- | --- | --- |
| 案 1 | OpenCV の HOG + SVM | **OpenCV が必要** | 低 (立位・正面のみ) | 不採用 |
| 案 2 | `torch` + `transformers` で HuggingFace の検出モデル | 無し (同梱済み) | 高 | 不採用 (起動が重く、重みも大きい) |
| **案 3** | **`onnxruntime` で ONNX の物体検出モデルを回す** | **無し (同梱済み)** | 高 | **採用** |
| 案 4 | 顔検出で代用 | — | — | **要件違反 (R2)** |

案 3 を採る理由:

* `onnxruntime` は既に配布物へ入っている (§2.4)。**R10 を守れるのはこの案だけ**である
  (案 2 も守れるが、`torch` のモデル読み込みは秒単位かかり、CPU 推論は ONNX Runtime より遅い)。
* 入出力が固定長テンソルだけなので、numpy だけで前処理・後処理を書ける。
* モデルを差し替えても呼び出し側は変わらない (`.onnx` を置き換えるだけ)。

使うモデルは **YOLOX-Tiny (Apache-2.0)** に確定した (§3.7.1)。

**人物クラスのみを残す**。COCO 系の検出器は 80 クラスを出すが、`person` (class 0) 以外は捨てる。

### 3.2 同一人物の判定 — 顔を使わない (R2)

要望は「顔で判断せず、服装を含めた身体全体で判断する」である。これは技術的にも都合が良い。

| 方式 | 内容 | 判定 |
| --- | --- | --- |
| 顔認識 | 顔を切り出して埋め込みを比較する | **不採用**。後ろ向き・マスク・低解像度で落ちる。生体情報を持つことになる |
| IoU トラッキングのみ | 前フレームの矩形との重なりで追う | 単独では不可。**セクションをまたげない** (§2.1) |
| **全身 ReID 埋め込み + IoU トラッキング** | 全身の切り抜きから外見特徴ベクトルを出し、距離で同一性を判定する | **採用** |

全身 ReID (Person Re-Identification) は、**服・髪・体型・持ち物を含めた見た目**を
数百次元のベクトルへ落とす。同じ動画の中では服装が変わらないため、
**離れたセクション間でも同一人物を高い精度で結べる** (R6 が成立する根拠)。

処理は 2 段階に分ける。

```text
① 区間内トラッキング (tracklet)   IoU + 埋め込み距離で、連続フレームの検出をつなぐ
② 全体クラスタリング (identity)   全 tracklet の平均埋め込みを距離でまとめ、人物 ID を振る
```

* ①で短い連続の塊 (tracklet) を作り、②で**全セクション横断の人物 ID** を決める。
* ②は単純な階層的クラスタリング (しきい値以下の距離を貪欲に統合) で足りる。ただし同じフレームの別々の位置に映る tracklet は統合しない (並んだ 2 人を 1 人にしないため)。
  `sklearn` は同梱されているが、**数百件程度の統合に外部ライブラリは要らない**ため numpy で書く。
* **限界**: 同じ動画内で着替えると別人物になる。原理上避けられないため、
  ぼかし指定画面で人物を手で統合できる操作を用意する (§5.6-6)。

### 3.3 「一番映っている人物」の決め方 (R3)

人物 ID ごとに **画面に映っていた合計秒数** (= 所属 tracklet の尺の和) を出し、最大のものを
「主役」とする。主役は既定で**ぼかさない**。

| 論点 | 決定 |
| --- | --- |
| 秒数の数え方 | **出力に含まれる区間だけ**を数える。カットされた区間・使用しないセクションは数えない (「動画」= 完成品と解釈) |
| 同点のとき | 先に登場した方を主役にする (決定的にするため) |
| 主役が 1 人も出ない (検出 0 件) | 主役無し。全員ぼかし対象の扱いになる |
| 主役を手で変えたい | ぼかし指定画面で「ぼかさない」を指定すれば同じ結果になるため、専用 UI は作らない |

### 3.4 建物 (静止物) の扱い (R7)

建物は COCO のクラスに無く、汎用の検出器では出せない。

| 案 | 内容 | 追加コスト | 判定 |
| --- | --- | --- | --- |
| 案 1 | セマンティックセグメンテーション (ADE20K の `building` クラス) で自動検出 | モデル 10〜50MB・推論が重い・ライセンスが不明瞭 | 不採用 (将来拡張 / §9-4) |
| **案 2** | **利用者が囲った領域を、位相相関で平行移動追従させる** | **無し** | **採用** |
| 案 3 | 囲った領域を固定 (追従しない) | 無し | **案 2 のフォールバックとして併用** |

案 2 の中身:

* 囲ったパスの外接矩形をテンプレートとして切り出す (グレースケール・縮小)。
* 次のサンプル時刻のフレームに対し、**FFT による位相相関**で平行移動量を求める
  (`numpy.fft` のみ。テンプレートマッチングの標準的な手法で、カメラのパン・手ぶれに強い)。
* 相関ピークの PSR (裾野の標準偏差の何倍突き出ているか) がしきい値を下回ったら「見失った」とみなし、
  `hold_sec` のあいだ直前の位置を保持してから打ち切る。
* **他セクションへの反映 (R6)** は、各セクションの先頭フレーム全体に対して
  同じ相関を取り、PSR がしきい値以上なら「同じ建物が映っている」と判定して追従を始める。

**限界**: 拡大縮小・回転には追従しない。ズームが入る素材では案 3 (固定領域) を選べるようにし、
ぼかし範囲に余白 (`margin_ratio`) を持たせて漏れを防ぐ。要望の「建物」は
看板・表札・窓といった**動かない被写体**を想定しているため、この割り切りで実用に足りると判断した (§9-4)。

### 3.5 ぼかしの焼き込み方式

対象は毎フレーム動く。FFmpeg で動く領域をぼかす方法は 3 つある。

| 案 | 内容 | 追加パス | 破綻する条件 | 判定 |
| --- | --- | --- | --- | --- |
| 案 1 | 対象ごとに `crop`+`boxblur`+`overlay` を並べ、`enable='between(t,…)'` で時間を切る | +0 | **フレーム数ぶんのフィルタが要る**。1 分 60fps で 3600 個。コマンド長が破綻する | 不採用 |
| 案 2 | **マスク動画を作り、`alphamerge`+`overlay` で合成する** | **+0** | マスク動画の生成コストのみ | **採用** |
| 案 3 | PyAV でデコードし、numpy でぼかして再エンコードする | +1 (全再エンコード) | Python で全フレーム処理 = 実時間の数倍 | 不採用 |

採用する案 2 のフィルタ (`movie=` ソースを使うため **`-i` は増えない** / §2.3):

```text
movie='<mask.mkv>',format=gray,scale=<W>:<H>[bmask];
[<in>]split=2[bkeep][bsrc];
[bsrc]gblur=sigma=<S>[bblur];
[bblur][bmask]alphamerge[bblura];
[bkeep][bblura]overlay=0:0:eof_action=pass[<out>]
```

* マスクは**グレースケール 1 本の動画**。白い所だけぼけた絵が乗る。
* `alphamerge` はマスクの輝度をそのままアルファにするため、**境界をぼかす (feather) と自然に溶ける**。
* `eof_action=pass` を必ず付ける。付けないとマスクが先に尽きたとき、
  FFmpeg は**最後のマスクを永久に繰り返す** (= 以降ずっと同じ位置がぼける)。
* ぼかしの種類は設定で選べるようにする。
  * `gaussian` … `gblur=sigma=S` (既定)
  * `pixelate` … `scale=iw/N:-1:flags=neighbor,scale=iw:ih:flags=neighbor` (モザイク)

マスク動画の作り方:

| 案 | 内容 | 判定 |
| --- | --- | --- |
| 案 A | PNG 連番を書き出して `-i mask_%06d.png` | 不採用 (10 分 60fps = 36000 ファイル) |
| 案 B | 生の rawvideo をファイルへ | 不採用 (480x270 gray で 10 分 = 約 4.6GB) |
| **案 C** | **PIL で描いて PyAV で可逆コーデックへエンコードする** | **採用** |

案 C なら、ほぼ真っ黒の絵が続くため**数 MB 以下**に収まる。PyAV は既に
`frame_source.py` が使っており、未導入環境のフォールバック (FFmpeg へ rawvideo をパイプ) も
同じ考え方で書ける (§5.4)。マスクは `mask_scale` (既定 0.25) に縮小して作り、
フィルタ側の `scale` で戻す。**ぼかしのマスクに原寸の精度は要らない**ためで、生成時間とサイズを 1/16 にできる。

### 3.6 解析をいつ走らせるか

| 案 | 内容 | 利用者から見た挙動 | 判定 |
| --- | --- | --- | --- |
| 案 1 | パイプラインの 1 工程として、Timeline 画面の前に必ず走らせる | 毎回 数分 待たされる。**使わない人にも掛かる** | 不採用 |
| **案 2** | **Timeline 画面を開いた直後に背後で走らせ、終わったらボタンを有効にする** | 画面はすぐ開く。字幕を直している間に解析が終わる | **採用** |
| 案 3 | ぼかし指定画面を開いたときに走らせる | ボタンを押してから数分固まる | 不採用 |

案 2 は要望 R4 の書きぶり (「Timeline 画面が開かれると、ぼかし指定画面が**開けるようになる**」)
とも一致する。ボタンは解析中「解析中… 42%」と出し、完了で「ぼかし指定...」へ変わる。
完了前に押された場合は進捗ダイアログを出して待たせる。

**解析対象は出力に含まれる区間だけ**にする (音声認識が残す区間だけを認識するのと同じ考え方)。
V1 のベースクリップが参照する `(media_id, source_in, source_out)` の集合がそのまま対象になる。
これにより、2 時間の VOD から 5 分ぶんを切り抜く場合の解析量は**5 分ぶん**で済む。

### 3.7 モデルの選定

必要なのは 2 つ。いずれも CPU 実行を前提とし、`onnxruntime` で読める `.onnx` 形式に揃える。

#### 3.7.1 人物検出 — **YOLOX-Tiny に決定**

| 候補 | 配布形式 | ライセンス | 判定 |
| --- | --- | --- | --- |
| **YOLOX-Tiny** | 公式が `.onnx` を配布 | **Apache-2.0** (コード・重みとも) | **採用** |
| YOLOX-Nano | 同上 | Apache-2.0 | 不採用。COCO AP 25.8 で取りこぼしが出る |
| YOLOv8n (Ultralytics) | 要エクスポート | **AGPL-3.0** | 不採用。有償配布の本製品とは相性が悪い |
| OpenVINO OMZ `person-detection-0200` | IR 形式 (要変換) | Apache-2.0 | 不採用。ONNX への変換工程が増える |

YOLOX-Tiny を採る理由:

* **Apache-2.0** であり、インストーラへの同梱と有償配布ができる。**検出側は §9-2 の論点が消える**。
* 公式が `.onnx` を配布しているため、**変換もエクスポートも要らない**。`onnxruntime` でそのまま読める。
* 入力が 416x416 と小さく、CPU でも 1 枚あたり数十 ms で回る (§5.3.6)。
* Nano (COCO AP 25.8) では通行人の取りこぼしが出る。privacy 目的の機能では
  **取りこぼしの損害が誤爆より大きい** (§9-1 と同じ理由) ため、1 段上の Tiny (COCO AP 32.8) を採る。
  ファイルは **約 20MB** (5.06M パラメータ x fp32 から算出。実ファイルの大きさは Phase 1 で確認する)
  と Nano より 16MB ほど大きいが、配布物全体から見れば誤差である。

**入出力の仕様。** `detector.py` が知っていればよいのは次だけである。

| 項目 | 内容 |
| --- | --- |
| 入力 | `float32[1, 3, 416, 416]` / **BGR のまま** / **0〜255 のまま (正規化しない)** |
| 前処理 | 縦横比を保って縮小し、余白を **114** で詰める (letterbox)。`scale = min(416 / h, 416 / w)` |
| 出力 | `float32[1, 3549, 85]`。3549 = 52² + 26² + 13²、85 = `cx, cy, w, h, obj, 80 クラス` |
| 後処理 | グリッド復元 → `obj x cls` をスコアにする → NMS → **class 0 (`person`) だけ残す** |
| 座標 | 復元した座標を `scale` で割ると元画像のピクセル座標へ戻る |

グリッド復元は、ストライド 8 / 16 / 32 のそれぞれについて
`x = (out_x + grid_x) * stride`、`w = exp(out_w) * stride` を当てるだけである。

> **注意: デコードは ONNX の中に入っていない。** 公式配布の `.onnx` は
> `--decode_in_inference` 無しでエクスポートされており、生のグリッド出力が出てくる。
> 上の後処理は numpy で 30 行程度で書けるため、**追加ライブラリは要らない** (§2.4 / R10)。

#### 3.7.2 全身 ReID — **OSNet-x0.25 に決定**

| 候補 | 配布形式 | ライセンス | 判定 |
| --- | --- | --- | --- |
| **OSNet-x0.25 (torchreid)** | 要エクスポート (`.pth` → `.onnx`) | **MIT** (コード) | **採用** |
| OpenVINO OMZ `person-reidentification-retail-0287` | IR 形式 (要変換) | Apache-2.0 | 不採用。OpenVINO の変換工程が要る |

OSNet-x0.25 を採る理由:

* **MIT** であり、表示さえ行えば同梱・有償配布ができる (§5.10)。
* **0.2M パラメータ**と極端に小さく、ファイルは **約 1MB** (fp32 から算出。Phase 1 で実測する)。
  1 人ぶんの推論が数 ms で終わるため、**1 フレームに数人いても検出のコストに埋もれる** (§5.3.6)。
* OSNet は**多尺度の特徴を混ぜる**構造で、服の色・柄・体型といった**全身の見た目**を拾う。
  R2 (顔で判断しない) の根拠がそのまま性能になる。
* 小さいわりに ReID の精度が高く、x0.25 でも Market-1501 で Rank-1 90% 前後が報告されている。
  **同じ動画の中は服装が変わらない**ため、本用途はベンチマークより易しい。

**入出力の仕様。** `reid.py` が知っていればよいのは次だけである。

| 項目 | 内容 |
| --- | --- |
| 入力 | `float32[1, 3, 256, 128]` (**縦 256 x 横 128**) / **RGB** / 0〜1 へ割る |
| 正規化 | ImageNet の mean `(0.485, 0.456, 0.406)` / std `(0.229, 0.224, 0.225)` |
| 前処理 | 検出した矩形を**縦横比を無視して 128x256 へ引き伸ばす** (ReID の作法。letterbox にしない) |
| 出力 | `float32[1, 512]` の特徴ベクトル |
| 後処理 | **L2 正規化**してから保存する。以降の比較は内積 = コサイン類似度で足りる |

検出器 (YOLOX / BGR・正規化なし・letterbox) と**前処理がまったく違う**点に注意する。
両者を 1 つの共通関数にまとめず、`detector.py` と `reid.py` がそれぞれ自前で持つ。

**`.onnx` の作り方。** torchreid の `osnet_x0_25` へ model zoo の重みを読ませ、
`torch.onnx.export` で書き出す。重みは **`osnet_x0_25_msmt17`** を第一候補とする
(MSMT17 は撮影条件の幅が広く、屋外配信への一般化が効きやすい。Market-1501 版でも動く)。

* この作業は**開発時に 1 回だけ**行い、できた `.onnx` をリポジトリへ入れる。
* したがって **`torchreid` も `torch` も配布物へ増えない** (R10 を維持)。
  `torch` は他機能の依存で開発環境に既にある (§2.4)。
* 手順は `tools/export_osnet.py` として残し、**どの重みのどの版から作ったか**を
  `docs/third_party_licenses.md` へ記録する (§5.10)。

#### 3.7.3 差し替え可能な形を保つ

2 つとも決まったが、次の 3 点は変えない。将来 YOLOX-S へ引き上げる余地 (§6) を残すためである。

* モデルのパス・入力サイズ・出力の解釈方法は `setting.json` の `blur.model` に持つ (R11)。
  モデル固有の前後処理は `model.detector_format: "yolox"` / `model.reid_format: "osnet"` で切り替える。
* `src/blur/detector.py` は「画像 → 矩形の列」、`src/blur/reid.py` は「画像 → ベクトル」しか公開しない。
* **モデルが見つからないときは機能ごと無効化**し、設定画面に理由を出す (例外で落とさない)。

## 4. 設計方針

1. **機能 OFF なら 1 行も通らない (R9)。** `blur.enabled` が False のとき、解析は起動せず、
   モデルも読まず、フィルタも 1 文字も増えない。既存の出力はバイト単位で変わらない。
2. **重いデータと軽いデータを分ける。** 検出結果 (トラック) は**キャッシュファイル**へ、
   利用者の指定 (誰をぼかすか) は**`timeline.source["blur"]`** へ置く。
   前者を `source` へ入れると Undo のたびに deepcopy されて画面が固まる (§2.6)。
3. **ぼかすのはベース映像だけ (R8)。** 字幕・コメントアイコン・オーバーレイ素材・透かしは
   ぼかしの後に載せる。マスクはベース映像に対してだけ効かせる。
4. **座標変換は 1 か所に閉じ込める。** 素材ピクセル → キャンバスピクセルの変換は
   `blur/geometry.py` だけが知る (§2.5)。他のモジュールはキャンバス座標しか扱わない。
5. **解析が失敗しても出力を止めない。** モデルの読み込み失敗・推論エラーは
   `src/blur/` の中で握り、「ぼかし指定は使えません」と画面へ出すだけにする。
   ただし**「ぼかすと指定したのに、ぼかさずに出力する」ことは絶対にしない** (§5.9 の扱い)。
6. **既存の出力経路の構造を変えない。** `renderer.render` の 3 分岐へチェーンを足すだけとし、
   ベース映像の構築 (`_render_base`)・連結・字幕焼き込みのロジックには触らない。
7. **調整値はすべて `setting.json` (R11)。** ただし設定画面に出すのは
   「使うかどうか」と「ぼかしの強さ・種類」だけにし、モデルやしきい値は出さない (§5.8)。

### 5.2 データモデル

#### 5.2.1 解析結果 (重い / キャッシュファイル)

保存先は**プロジェクトファイルの隣** (`<プロジェクト名>.blur.json`)。
プロジェクト未保存なら `PipelineContext.working_dir` (実行終了で消える)。

```jsonc
{
  "schema": 1,
  "generator": "Stretheus 1.4.8",
  "fingerprint": "…",            // §5.3.4。合わなければ作り直す
  "canvas": {"width": 1920, "height": 1080},
  "sample_fps": 5.0,
  "identities": [
    {
      "id": "p1",
      "total_sec": 612.4,          // 出力に含まれる区間で映っていた合計 (§3.3)
      "main": true,                // 一番映っている = 主役 (R3)
      "embedding": [0.01],         // 平均特徴ベクトル (OSNet-x0.25 = 512 次元 / L2 正規化済み)
      "thumb": "<base64 PNG>",     // 一覧に出す小さな見本 (96px 程度)
      "tracks": ["t1", "t7", "t12"]
    }
  ],
  "tracks": [
    {
      "id": "t1",
      "identity": "p1",
      "media_id": "m1",            // どの素材の話か (アーカイブ用は複数ある)
      "kind": "person",            // person | region
      "start_sec": 12.0,           // 素材内の時刻
      "end_sec": 35.2,
      "samples": [                 // 素材ピクセル座標。sample_fps 間隔
        {"t": 12.0, "x": 820, "y": 140, "w": 260, "h": 620, "score": 0.91}
      ]
    }
  ]
}
```

* `samples` は `sample_fps` (既定 5) の間隔でしか持たない。**中間の時刻は線形補間**する (§5.4)。
  60fps の全フレームを持つと 10 分で 36000 件になるため持たない。
* 素材ピクセル座標で持つ。キャンバスへの変換は描画時に行う (§4-4)。

#### 5.2.2 指定 (軽い / `timeline.source["blur"]`)

Undo と保存が自動で効く (§2.6)。**1KB 程度に収まる大きさしか置かない。**

```jsonc
"blur": {
  "version": 1,
  "cache": "sample.timeline.blur.json",   // 解析結果の場所 (プロジェクトからの相対)
  "fingerprint": "…",                     // キャッシュと突き合わせる
  "default_policy": "blur_others",        // §9-1。blur_others | manual_only
  "identities": {"p1": "keep", "p3": "blur"},   // 明示指定のみ持つ
  "merges": [["p2", "p5"]],               // 同一人物として手で統合した組 (§5.6.6)
  "regions": [
    {
      "id": "r1", "mode": "blur", "label": "建物A",
      "media_id": "m1", "anchor_sec": 84.5,
      "path": [[0.41, 0.22], [0.55, 0.22], [0.55, 0.61], [0.41, 0.61]],
      "follow": "track"                   // track (追従) | fixed (固定)
    }
  ]
}
```

* `identities` は**明示された人物だけ**を持つ。触っていない人物は `default_policy` に従う。
  主役 (R3) は `default_policy` に関わらず常に `keep` 扱いとし、ここに書かなくても除外される。
* `regions[].path` は**正規化座標** (キャンバス幅・高さに対する 0.0〜1.0) で持つ。
  出力解像度が変わっても指定が生きる。
* `region` の追従結果 (時刻ごとの位置) は解析結果と同じくキャッシュ側へ書く (`kind: "region"` のトラック)。

### 5.3 解析 (`analyzer.py`)

#### 5.3.1 入口

```python
# Timeline から解析対象の区間を決め、検出 → トラッキング → クラスタリングまで行う。
# on_progress: (0.0〜1.0, ラベル) を受け取るコールバック。cancel: 中断確認の callable。
def analyze(timeline, settings, cache_path, on_progress=None, cancel=None) -> dict
```

#### 5.3.2 対象区間の決定

V1 のベースクリップが参照する `(media_id, source_in, source_out)` を集め、
同じ素材の重なり・隣接をまとめる。使用しないクリップ (`enabled=False`) は含めない。

```python
spans = [(c.media_id, c.source_in, c.source_out) for c in timeline.base_clips()]
```

OP / ED のクリップ (`clip.is_opening_or_ending()`) は**対象外**にする
(毎回同じ定型素材であり、解析しても意味が無いため)。
これにより、2 時間の VOD から 5 分ぶんを切り抜く場合の解析量は**5 分ぶん**で済む。

#### 5.3.3 1 区間の処理

```text
PyAV で区間をデコード (frame_source と同じ手口。seek してから前進デコード)
  → sample_fps の間隔で 1 枚取り出す
  → detector.detect(frame)            人物の矩形 (YOLOX-Tiny / 416x416 / person のみ)
  → reid.embed(frame, boxes)          矩形ごとに全身の特徴ベクトル (OSNet-x0.25 / 512 次元 / R2)
  → tracker.update(t, boxes, embeds)  IoU + 埋め込み距離で tracklet へつなぐ
```

* `sample_fps` (既定 5) は品質と時間の取引になる。設定で変えられるようにする (§5.8)。
* デコードは `frame_source.PyAvFrameSource` と同じ考え方だが、**前進デコード専用**の
  軽い実装を `analyzer` 内に持つ (プレビューとキャッシュや状態を共有しない)。
* PyAV が使えない環境では、FFmpeg へ `-vf fps=N -f rawvideo` でパイプさせる経路へ倒す
  (`frame_source` が既に同じ二段構えになっている)。
* `cancel()` が True を返したらその場で中断し、`None` を返す (結果はキャッシュしない)。

#### 5.3.4 指紋 (fingerprint)

キャッシュの整合性は、次を連結した文字列の SHA-256 で判定する。

```text
元動画のパス + サイズ + 更新時刻 + キャンバス幅 x 高さ + sample_fps + モデル名 + モデルの版
```

`source.media_path` (正規化後の一時ファイル) は毎回変わるため使わない。
**`source.input_path` (元動画)** を使うことで、プロジェクトを開き直しても同じ指紋になり、
**2 回目以降は解析を省略できる**。

#### 5.3.5 進捗とスレッド

* `QThread` で走らせ、優先度は `QThread.LowPriority` にしてプレビュー再生を邪魔しない。
* 進捗は「処理した秒数 / 対象の合計秒数」で出す。
* Timeline 画面を閉じるときは必ず停止を待つ (`wait()`)。

#### 5.3.6 処理時間の見積もり

| 項目 | 見積もり | 根拠 |
| --- | --- | --- |
| 検出 (1 枚) | 15〜40ms | YOLOX-Tiny (416x416) を CPU で推論 |
| ReID (1 人ぶん) | 3〜10ms | OSNet-x0.25 (128x256 / 0.2M パラメータ) |
| 合計 (本編 10 分 / 5fps / 平均 2 人) | **1.5〜4 分** | 3000 枚 x (検出 + 2 人ぶんの ReID) |

**この見積もりは Phase 1 の完了条件で実測して差し替える。** 想定を大きく超える場合は
`sample_fps` の既定を下げる。YOLOX-Tiny は入力が既に 416 と小さいため、
**解像度を落とす前に `sample_fps` を下げる**方が精度あたりの効きが良い。

### 5.4 マスク生成 (`mask_builder.py`)

```python
# Timeline・解析結果・指定から、Timeline 時間のマスク動画を 1 本作る。
# ぼかす対象が 1 つも無ければ None を返す (= フィルタを足さない)。
def build(timeline, analysis, decisions, cfg, out_path, on_progress=None) -> str | None

# renderer から呼ぶ入口。設定・キャッシュ・指定を読み、必要なときだけ build へ回す。
# 機能 OFF / 指定なし / キャッシュ不一致のいずれでも None を返す (= 従来どおりの出力)。
def prepare(timeline, context, cfg) -> str | None
```

手順:

1. `TimeMap.from_timeline(timeline)` を作る (`src/timeline/timemap.py:71`)。
2. 出力フレーム (0 〜 `timeline.duration_sec()` を `fps` 刻み) ごとに、
   `to_source()` で「どの素材の何秒か」を引く。
3. その時刻に生きているトラックのうち、**ぼかすと決まったもの**を集める。
   * `kind == "person"` → `identity` を引き、§5.2.2 の規則で `blur` / `keep` を決める
   * `kind == "region"` → `regions[].mode` をそのまま使う
4. `samples` を線形補間して矩形を求め、`margin_ratio` ぶん広げる。
5. `geometry.source_to_canvas()` でキャンバス座標へ直す (§2.5)。
6. PIL の `ImageDraw` で白く塗る (人物 = 角丸矩形 / 領域 = 多角形)。
   絵は `mask_scale` (既定 0.25) に縮小した大きさで作る。
7. `ImageFilter.GaussianBlur(feather_px)` で境界をぼかす → 合成時に自然に溶ける (§3.5)。
8. PyAV でグレースケールの可逆動画 (`ffv1` / `.mkv`) として書き出す。

補足:

* 取りこぼし対策として、各トラックの区間を `pad_sec` (既定 0.2 秒) ぶん前後へ伸ばす。
  検出は 1 サンプルおきのため、出入りの瞬間に素の被写体が 1〜2 フレーム出る事故を防ぐ。
* 全フレーム真っ黒になる場合は**マスクを作らない** (`None`)。余計な合成パスを走らせない。
* アーカイブ用のサブ Timeline に対しても同じ関数を呼ぶ。サブ Timeline は 0 起点へ
  ずらされている (`_build_group_timeline`) が、`TimeMap` をその Timeline から作るため
  そのまま正しい時刻になる。

#### 5.5.3 未適用のまま出力しない保険


既定はどちらも「無し」のため、**ポイント機能やぼかし機能を通らない呼び出し
(CLI / テスト) では従来と完全に同じ挙動**になる。
`output_writer.run` と `clip_writer.finish_clips` の出力直前で `is_required()` を確認し、
True なら単独パスを足す。**経路が増えても「出力の直前に必ず確認する」1 点で守れる。**

#### 5.5.4 アーカイブ用の `source` 引き継ぎ (§2.8)

```python
# src/archive/timeline_builder.py _build_group_timeline
sub.media_pool = list(timeline.media_pool)
sub.source = dict(timeline.source or {})   # ← 追加。ぼかし指定を書き出しへ運ぶ
```

`source` は浅いコピーで足りる (書き出しは読むだけ。メディアプールと同じ方針)。
この 1 行が無いと**アーカイブ用の出力だけぼかしが消える**ため、

### 5.6 ぼかし指定画面 (R4 / R5)

#### 5.6.1 開き方

#### 5.6.2 画面構成

```text

│  フレーム表示 (QGraphicsScene/キャンバス座標)   │ [見本] 主役   │
```

* フレームの取得は既存の `frame_source.create_frame_source` (`:316`) を使い回す。
* スクラバはセクションの境界に目盛りを出す。「セクション」のコンボで頭出しできる。
* 検出枠は**その時刻に生きているトラック**を描き、現在の指定で塗り分ける。

#### 5.6.3 パスで囲う操作 (R5)

1. 「ぼかす」「ぼかさない」のどちらのモードかを選ぶ。
2. フレームの上をドラッグして自由曲線を描く (`QPainterPath`)。離すと自動で閉じる。
3. 囲みの中に**検出枠の中心が入っている**人物を拾う。中心が外でも、
   **枠と囲みの重なりが `hit_ratio` (既定 0.5) 以上**なら採用する。
4. 結果で分岐する。

| 囲みの中身 | 扱い |
| --- | --- |
| 人物が 1 人以上 | その**人物 ID 全体**へモードを設定する (= 全セクションへ反映 / R6) |
| 人物が 0 人 | **領域 (建物など)** として登録し、追従を開始する (§3.4) |
| 主役を囲んで「ぼかす」 | 確認を出す (「一番映っている人物です。ぼかしますか」) |

5. 反映の内容を要約して見せる。

```text
人物 2 をぼかします。
  該当: 3 セクション / 12 区間 / 合計 3 分 40 秒
```

#### 5.6.4 全セクションへの反映 (R6)

人物の場合、反映は**指定の書き換えだけ**で完了する。

```text
指定は人物 ID に対して行う
  → その人物 ID に属する tracklet は、解析の時点で全セクションから集めてある (§3.2 ②)
  → マスク生成 (§5.4) が Timeline 全体を走査するため、全セクションへ自動で効く
```

つまり「全セクションを見直す」処理は**解析の時点で済んでいる**。画面は該当件数を数えて見せるだけでよい。
これが §3.2 で ReID を採った理由である (トラッキングだけではセクションを跨げない)。

領域 (建物) の場合は指定の時点で追従が要るため、囲んだ直後に短い処理を走らせる。

```text
1. 囲んだフレームからテンプレートを切り出す
2. 同じ素材の他の区間 … 前後へ位相相関で追従する
3. 他の素材 (アーカイブの他セクション) … 各セクションの先頭フレーム全体と相関を取り、
   PSR がしきい値以上なら「同じ建物が映っている」として追従を始める
4. 得られた軌跡を kind="region" のトラックとしてキャッシュへ足す
```

進捗は `QProgressDialog` で見せ、キャンセルできるようにする
(`archive_timeline_dialog._start_section_worker` と同じ作り)。

#### 5.6.5 Undo/Redo

指定の変更は `commands.Command` の派生として実装し、`CommandStack` へ積む。

```python
class SetBlurDecision(commands.Command):      # 人物 1 人ぶんの指定
class AddBlurRegion(commands.Command):        # 領域の追加
class RemoveBlurRegion(commands.Command):     # 領域の削除
class MergeBlurIdentities(commands.Command):  # 人物の統合 (§5.6.6)
```

`_snapshot` が `source` を deepcopy するため (§2.6)、`apply` の中で
`timeline.source["blur"]` を書き換えるだけで Undo が効く。**Timeline 編集画面の
「元に戻す」からぼかし指定も戻せる**ため、利用者から見て操作の一貫性がある。

#### 5.6.6 人物の統合 (§3.2 の限界への対処)

一覧の 2 人を選んで「同じ人物にする」を実行できるようにする。
着替え・長時間の不在で人物 ID が割れた場合の救済で、統合結果は
`source["blur"].merges` へ持つ。**解析をやり直しても統合の指定は残る。**

### 5.7 プレビューへの反映

Timeline 編集画面のプレビューでも、ぼかしの当たり具合が分かるようにする。

* 再生ヘッドの位置で、ぼかす対象の矩形を**半透明の塗り + 「ぼかし」ラベル**で重ねる。
* **実際のぼかし処理はしない。** プレビューは 1 枚ずつ取得しており
  (`preview_panel._request_frame`)、ここへ画像処理を足すとスクラブが目に見えて重くなる。
* 表示の ON/OFF は設定で切り替えられるようにする (`blur.preview_marker`)。

### 5.8 設定画面 (R1)

「一般」タブは既に項目が多いため、**「ぼかし」タブを新設**する
(`settings_window._build_ui` の `tabs.addTab` へ 1 行足す / `:1186`)。

| 項目 | ウィジェット | 対応する設定 |
| --- | --- | --- |
| トラッキングぼかし | チェック「トラッキングぼかしを使用する」 | `blur.enabled` |

| ぼかしの強さ | 数値 (1〜100) | `blur.render.strength` |

### 5.9 ログとエラー処理

既存の `utils.logger.get_logger` に従う。

| 事象 | 扱い |
| --- | --- |
| モデルが見つからない | WARNING。機能を無効化し、設定画面とツールチップに理由を出す |
| 推論に失敗 (1 フレーム) | DEBUG。そのフレームを飛ばして続行する |
| 解析全体が失敗 | ERROR。「ぼかし指定は使えません」を画面へ出す。**Timeline 編集と出力は続行できる** |
| マスク生成に失敗 | ERROR + 出力前に確認ダイアログ (「ぼかしを入れずに出力 / 中止」) |
| キャッシュが壊れている | WARNING。捨てて解析し直す |

**マスク生成の失敗だけは黙って続行しない。**「ぼかすと指定したのに素で出た」が
最も損害の大きい失敗であり、利用者に選ばせる必要がある (§4-5)。

#### 5.10.2 リポジトリ上の置き場とビルドでの流し込み

リポジトリ直下へ `licenses/` を置き、**リリース手順で `dist/Stretheus/` へそのままコピーする**。


`.onnx` 本体は従来どおり `main.spec` の `datas` で `_internal/src/models/` へ入れる (§8-3)。

#### 5.10.3 アプリからの導線

#### 5.10.4 既存の抜けについて

現在の配布物には `licenses/` に相当するものが**そもそも無い**。FFmpeg (LGPL/GPL)・
PySide6 (LGPL)・onnxruntime (MIT)・faster-whisper (MIT) なども表記が要るはずで、
**これはぼかし機能とは別に前からある抜け**である。

今回作る `licenses/` は**そのまま受け皿になる**ため、本機能のぶん (YOLOX / torchreid) を
入れるついでに既存ぶんも同じ場所へ足すことを勧める。ただし依存の棚卸しが要るため
**本設計の作業範囲には含めない**。判断は §9-2 へ挙げた。

## 6. 実装手順

「動くものを先に作り、速さと精度は後から足す」。ver5 resolve と同じ進め方にする。

| Phase | 内容 | 完了条件 |
| --- | --- | --- |
| 0 | `tools/export_osnet.py` で OSNet-x0.25 を ONNX へ書き出す (§3.7.2) | `osnet_x0_25.onnx` ができ、同じ画像で PyTorch 版と**出力ベクトルが一致する** (誤差 1e-4 以下) |
| 1 | `models.py` / `detector.py` / `reid.py` (ONNX の読み込みと推論) | YOLOX-Tiny と OSNet-x0.25 の `.onnx` を読み、静止画 1 枚から人物の矩形と特徴ベクトルが出る。**1 枚あたりの実測値とファイル容量を §3.7 / §5.3.6 へ反映する** |
| 2 | `tracker.py` / `analyzer.py` / `store.py` (解析とキャッシュ) | 2 セクション以上に同じ人物が映る素材で、**同じ人物 ID** にまとまる。主役が正しく選ばれる (R3) |
| 3 | `mask_builder.py` / `geometry.py` / `blur_overlay.py` | マスク動画が作れ、`ffplay` で位置が合っている。縦動画 (1080x1920) でもずれない (§2.5) |
| 4 | `renderer` の 3 分岐と出力直前の保険への組み込み + §5.5.4 の 1 行 | クリップ用・アーカイブ用の両方でぼかしが焼き込まれる。**セクション 2 本以上で両方に入る** |
| 5 | `blur_spec_dialog.py` / `blur_canvas.py` (囲み指定・一覧・Undo) | 囲んだ人物が全セクションでぼける / ぼけない (R5 / R6) |
| 6 | `region_tracker.py` (建物の追従) と他セクションへの当て込み | パンする素材で建物が追従する。見失ったら保持して打ち切る (R7) |
| 7 | 設定画面の「ぼかし」タブ (R1) とプレビューの目印 | チェックを外すと**ボタンも解析も出ない**。既存テストが全件通る |
| 8 | `main.spec` へのモデル同梱・**`licenses/` の同梱 (§5.10)**・`docs/` 更新・リリース手順の追記 | 凍結配布で動く (§8-3)。**インストール後のフォルダに `licenses/` がある**。設定画面のボタンから開ける |

Phase 4 までで「設定ファイルを手で書けばぼかせる」状態になり、
Phase 5 で初めて利用者の操作が繋がる。**検出の精度は Phase 2 の時点で評価できる**ため、
YOLOX-Tiny で足りるかの判断はこの時点で行う。足りない場合の引き上げ先は
**YOLOX-S (640 入力 / Apache-2.0 / 約 36MB)** とし、`blur.model` の 2 行を変えるだけで差し替わる (§3.7.3)。

## 7. setting.json 定義

```jsonc
"blur": {
  // ── 機能の有効化 (R1)。false のとき解析もボタン表示も一切行わない
  "enabled": false,

  // 囲っていない人物をどう扱うか (§9-1)
  //   "blur_others" = 主役以外はぼかす / "manual_only" = 囲ったものだけぼかす
  "default_policy": "blur_others",

  // プレビューへぼかし対象の目印を出す (§5.7)
  "preview_marker": true,

  // ── モデル (設定画面には出さない)
  "model": {
    "detector": "models/yolox_tiny.onnx",        // src/ からの相対パス。Apache-2.0 (§3.7.1)
    "detector_format": "yolox",                  // 出力の解釈方法。差し替えの切り替え点 (§3.7.3)
    "detector_input": 416,                       // 入力の一辺 (px)。YOLOX-Tiny は 416
    "detector_pad_value": 114,                   // letterbox の余白色 (YOLOX の既定)
    "detector_score": 0.4,                       // 採用する最低スコア (obj x cls)
    "detector_nms": 0.5,                         // NMS の IoU しきい値
    "reid": "models/osnet_x0_25.onnx",           // OSNet-x0.25 / MIT (§3.7.2)
    "reid_format": "osnet",                      // 前後処理の切り替え点 (§3.7.3)
    "reid_input": [128, 256],                    // 幅 x 高さ (縦横比は無視して引き伸ばす)
    "reid_dim": 512,                             // 出力ベクトルの次元。L2 正規化して保存する
    "providers": ["CPUExecutionProvider"]        // onnxruntime の実行プロバイダ
  },

  // ── 解析 (設定画面に出すのは sample_fps だけ)
  "analysis": {
    "sample_fps": 5.0,        // 1 秒あたり何枚を検出にかけるか
    "auto_start": true,       // Timeline 画面を開いた直後に背後で始める (§3.6)
    "min_track_sec": 0.6,     // これより短い tracklet は捨てる (誤検出よけ)
    "iou_threshold": 0.3,     // 連続フレームを同一とみなす重なり
    "embed_threshold": 0.35,  // 同一人物とみなす特徴ベクトルの距離 (コサイン距離)
    "merge_threshold": 0.30,  // 全体クラスタリングで統合する距離 (§3.2 ②)
    "max_identities": 50      // 人物 ID の上限 (これを超えたら短いものから捨てる)
  },

  // ── 領域 (建物など / §3.4)
  "region": {
    "follow": "track",        // track = 位相相関で追従 / fixed = 固定
    "search_scale": 0.5,      // 相関を取るときの縮小率 (速度のため)
    "match_psr": 25.0,        // 相関ピークの PSR がこれを下回ったら見失ったとみなす
    "hold_sec": 1.0           // 見失ってから位置を保持する時間
  },

  // ── ぼかしの見え方。大きさはキャンバス幅に対する比率で決める (watermark と同じ方針)
  "render": {
    "mode": "gaussian",       // gaussian | pixelate
    "strength": 50,           // 1〜100。sigma / モザイク片 = キャンバス幅 x 0.00025 x strength
    "margin_ratio": 0.06,     // 検出枠を広げる量 (枠 / 幅の比)
    "feather_ratio": 0.006,   // 境界をぼかす量 (キャンバス幅比)
    "pad_sec": 0.2,           // トラックの前後へ伸ばす時間 (取りこぼし対策)
    "mask_scale": 0.25,       // マスクを作る解像度 (キャンバスに対する比)
    "shape": "rounded"        // rounded | rect | ellipse (人物の塗り方)
  },

  // ── 指定画面
  "spec": {
    "hit_ratio": 0.5,         // 囲みと検出枠の重なりがこの比率以上なら選択とみなす
    "thumb_px": 96            // 人物一覧に出す見本の一辺
  }
}
```

* **既定は `enabled: false`。** 既存利用者の挙動を変えないためで、
  使う人が設定画面で明示的に有効化する (R1 / R9)。
* `strength` だけを設定画面に出し、`sigma` や `mask_scale` は出さない (§5.8)。
* 既存の `settings_window._merge_with_defaults` により、**旧 `setting.json` にも
  起動時に `blur` セクションが補われる** (`_fill_nested_defaults` と同じ扱いにする)。

## 8. 互換性・非破壊の担保

1. **機能 OFF が既定 (R9)。** `blur.enabled = false` のとき、
   `renderer` は従来と 1 文字も変わらないコマンドを組む。処理時間も変わらない。
2. **`PipelineContext` の新フィールドは既定「無し」。** CLI / テストからの呼び出しは影響を受けない。
   ぼかしの有無に関わらず `renderer.render` の引数も戻り値も変わらない。
3. **凍結配布 (PyInstaller)。** `src/main.spec` の `datas` には現在
   `comment_icon.png` と BudouX しか入っておらず、**`watermark.png` すら入っていない**。
   Phase 8 で `models/yolox_tiny.onnx` (約 20MB) と `models/osnet_x0_25.onnx` (約 1MB) を追加する。
   **配布物はその分だけ増える** (合計 約 21MB)。`onnxruntime` は既に配布物へ入っているが、
   遅延 import のため `hiddenimports` への追記が要るかを実際のビルドで確認する。
   **`licenses/` は `datas` では入らない** (onedir では `_internal/` 配下へ行くため)。
   リリース手順のコピーで exe 直下へ置く (§5.10.2)。
4. **既存テスト 662 件を壊さない** (`python -m unittest discover -s tests`)。
   ぼかしの処理はすべて「既定で無効」の分岐の内側に入るため、既存の出力経路は変わらない。
5. **プロジェクトファイルの互換性。** 指定は `source` の追加キーとして入るため、
   スキーマ版 (`project_io.SCHEMA_VERSION`) を上げる必要は無い。
   **旧アプリで開いても `blur` キーが無視されるだけ**で壊れない。逆に新アプリで
   旧プロジェクトを開いた場合は「指定なし」として扱われる。
6. **モデルが無い環境でも起動する。** `models/` が空でもアプリは通常どおり動き、
   設定画面に「モデルが見つかりません」と出るだけにする。
7. **解析キャッシュは消えてよい。** `<プロジェクト名>.blur.json` を消しても、
   指定 (`source["blur"]`) が残っていれば**次に開いたときに解析をやり直して復元できる**
   (人物 ID は指紋が同じなら同じ採番になるよう、tracklet の登場順で決定的に振る)。

## 9. 確認事項

| # | 論点 | 推奨 | 反映先 |
| --- | --- | --- | --- |
| 1 | **囲っていない人物をどうするか** | **主役以外は既定でぼかす (`blur_others`)** | §5.2.2 / §7 |
| 2 | **同梱するモデルとライセンス** | **決定済み** (YOLOX-Tiny / OSNet-x0.25)。`licenses/` を同梱する | §3.7 / §5.10 |
| 2-b | 既存の同梱物 (FFmpeg / PySide6 等) の表記も同時に直すか | **勧めるが本設計の範囲外**。同じ `licenses/` へ足せる | §5.10.4 |
| 3 | DaVinci Resolve 書き出しのぼかし | **当面は非対応。書き出し時に注意を出す** | §9-3 |
| 4 | 建物の自動検出 | **今回は入れない。**囲って追従させる方式のみ | §3.4 |
| 5 | 解析結果の保存先と寿命 | プロジェクトの隣 (`.blur.json`)。プロジェクト削除時に一緒に消す | §5.2.1 |
| 6 | レガシーモードでの扱い | **対象外。**Timeline 画面が無く R4 が成立しない | §2.2 |
| 7 | 縦動画 (`vertical`) での扱い | 対応する。座標変換で吸収する (§2.5) | §5.4 |

### #1 の詳細 — ぼかしの既定方針

要望は「一番映っている人物はぼかしをかけない」「囲って ぼかす / ぼかさない を指定する」の 2 つで、
**囲っていない人物 (通行人など) をどうするか**が書かれていない。読み方は 2 通りある。

| 方針 | 挙動 | 向いている使い方 |
| --- | --- | --- |
| **`blur_others` (推奨)** | 主役以外は自動でぼかす。囲むのは「この人はぼかさなくてよい」という**例外指定** | 外配信・イベント。**映り込みを取りこぼさない** |
| `manual_only` | 囲った人だけぼかす | 屋内配信。誤爆を避けたい |

推奨は `blur_others`。「一番映っている人物はぼかさない」という但し書きは、
**既定でぼかすからこそ意味を持つ**表現だと読める。また privacy 目的の機能では、
**取りこぼし (ぼかし忘れ) の損害が誤爆 (余計にぼけた) より大きい**。
ただし両方を設定で選べるようにしてあるため、決定が変わっても実装は変わらない。

### #2 の詳細 — モデルとライセンス (決定済み)

本製品は有償配布 (ポイント制 / サブスク) のため、**AGPL / 非商用限定の重みは使えない**。
Ultralytics 系 (YOLOv5 / v8 / 11) は AGPL-3.0 であり、そのままでは採用できない。

**2026-09-16 に次を決定した。**

| 用途 | モデル | ライセンス | 同梱物 | 大きさ |
| --- | --- | --- | --- | --- |
| 人物検出 | **YOLOX-Tiny** | Apache-2.0 | 公式配布の `.onnx` をそのまま | 約 20MB |
| 全身 ReID | **OSNet-x0.25** (torchreid) | MIT | `.pth` から自前で ONNX へ変換 (§3.7.2) | 約 1MB |

どちらも**表示さえ行えば同梱・有償配布ができる**ため、残る作業は表記だけである。

### 帰属表示 — `licenses/` をインストールフォルダへ置く (§5.10)

| ライセンス | 求められること | 本設計での対応 |
| --- | --- | --- |
| Apache-2.0 | ライセンス全文の添付 / 著作権表示 / NOTICE があればその引き継ぎ | `licenses/YOLOX/` に全文と NOTICE を置く |
| MIT | 著作権表示とライセンス文の添付 | `licenses/torchreid/LICENSE.txt` に全文を置く |

* 置き場は **exe と同じ階層** (`_internal/` の中ではない)。利用者がフォルダを開けば見つかる。
* 設定画面の「ライセンス表記を開く」ボタンからも開ける (§5.10.3)。
* **どの版の重みから作ったか**を `README.txt` と `docs/third_party_licenses.md` へ記録する。
  再現できないと、後で「何を配ったか」が分からなくなるためである。

### 残る確認 (法務判断。設計・実装は止めない)

* ReID の重み (`osnet_x0_25_*`) は **Market-1501 / MSMT17 で学習されたもの**である。
  torchreid のコードは MIT だが、**学習に使われたデータセットは研究用途を前提に配布されている**。
  学習済み重みを商用製品へ同梱してよいかは、データセット側の規約を確認しておきたい。
* 判断が保留になる場合の逃げ道は 2 つあり、**いずれも設計は変わらない** (§3.7.3)。

| 案 | 内容 | 影響 |
| --- | --- | --- |
| 案 A | 初回有効化時に重みをダウンロードする | ネット必須。配布サイズは増えない |
| 案 B | ImageNet 事前学習のみの重みを使う | 同定の精度が落ちる。同一動画内なので実用上は耐える見込み |

なお**検出だけでも機能は成立する** (同一人物の結び付けが区間内に限られ、R6 の精度が落ちる)。
最悪の場合は ReID 無しで先に出し、後から足すこともできる。

### #3 の詳細 — Resolve 書き出し

`export/fcpxml_builder.py` が出す FCPXML には**ぼかしを表現する手段が無い**
(追従するマスクは Resolve のエフェクト側の情報であり、FCPXML の互換範囲を超える)。

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **案 1** | ぼかし無しで書き出し、**書き出し時に「ぼかしは含まれません」と出す** | **推奨** |
| 案 2 | マスク動画を隣へ書き出し、Resolve で手動合成してもらう | 案内が必要。将来 |
| 案 3 | ぼかし済みの中間動画を素材として書き出す | カット編集のやり直しができなくなる |

案 1 を推奨する。Resolve へ持っていく利用者は自分で加工する前提であり、
**黙ってぼかし無しで出すことだけは避ける**のが目的である。

### #4 の詳細 — 建物の自動検出を今回入れない理由

* 建物は COCO 系の検出器では出せず、セマンティックセグメンテーションが要る (§3.4)。
* 自動検出すると「街全体がぼける」ことになり、**利用者が望む結果になりにくい**。
  実際に隠したいのは建物そのものではなく、**表札・看板・番地・窓**といった一部である。
* 囲って指定する方式なら、その一部だけを狙って隠せる。
* 将来、自動検出を足す場合も**囲み指定の仕組みはそのまま使える** (候補を自動で提案するだけ)。
