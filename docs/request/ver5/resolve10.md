# resolve10（ver5） — アーカイブ切り抜きから縦動画プロジェクトを作る 詳細設計書

## 0. 本書の位置づけ

* 対象: **アーカイブ切り抜き用 Timeline の右クリックから、Shorts 用の縦プロジェクトを作れるようにする。**
  素材は**元 VOD を参照**させる。
* `resolve9.md` §3.7 / §10 #4 で「アーカイブ用からは作れない」と決めた判断の**改訂**にあたる。
  resolve9 の該当箇所は本書を指すよう書き換えた。
* 要望 (2026-09-29): 「アーカイブ用から新規 short 用プロジェクトを作成させることが大事。
  クリップ用で作ってしまった処理はそのままでよい。元 VOD を参照するようにしてほしい。
  既存の処理は壊したくない。」
* 調査は **2026-09-29 時点の実コード**を読んで行った。

### 0.1 一言でいうと

**保存の直前に、素材を「消える中間ファイル」から「元 VOD」へ張り替える。**

アーカイブ用 Timeline の素材は、VOD から `-c copy` で切り出したクリップ単位の中間ファイルで、
実行の終わりに消える。編集中は実体があるので画面もプレビューもそのまま使える。
**縦プロジェクトを書き出す瞬間だけ**、素材の参照先を元 VOD へ向け直し、
クリップの素材内時刻に「切り出しの先頭」を足して VOD 基準へ直す。

```
編集中 (アーカイブ用 Timeline)          保存される縦プロジェクト
  m1 = <temp>/media_m1/normalized.mp4     vod = D:/archive_work/v123.mp4
  c1: source_in = 2.0            ──→      c1: source_in = 12.0
       (m1 の 2.0 秒)                          (VOD の 12.0 秒 = 10.0 + 2.0)
```

切り出しも再エンコードも行わない。**resolve9 §4-2「指定だけを持つ」と同じ方針**である。

### 0.2 この設計で**やらないこと**

| やらないこと | 理由 |
| --- | --- |
| 音量の正規化を引き継ぐ | 正規化はクリップ単位の 2 パス測定で、VOD 全体へは当てられない。作成時に知らせる (§3.4) |
| アーカイブ用の書き出し経路を変える | 要望どおり触らない。張り替えは縦プロジェクトの作成時にしか動かない (§4-1) |
| 中間ファイルを残す / 縦用に切り出す | 中間ファイルが増えるうえ、resolve9 の「指定だけを持つ」方針と食い違う |
| クリップ用からの作成を変える | `rebase` を渡さなければ従来と同じ経路をそのまま通る (§4-1) |

## 2. 調査 — なぜ `vod_start` を足してはいけないか

`archive/timeline_builder.py` は素材 1 本ごとに「どの VOD 区間から作ったか」を
`source.archive.media` へ残している。

```jsonc
{"media_id": "m1", "vod_start": 100.0, "vod_end": 160.0, "media_role": "normalized"}
```

既存の `media_vod_ranges()` は **`vod_start` + 素材内の秒 = VOD の秒**として扱っている。
これは「その素材がどのあたりを使っているか」を知るには十分だが、**切り抜きには使えない**。

素材を作っている `clip_writer.cut_region()` はこうである。

```python
ffmpeg -ss <start> -i <vod> -t <duration> -c copy -avoid_negative_ts make_zero <dest>
```

FFmpeg の入力側 `-ss` は、**ストリームコピーではシーク点と要求位置の間を捨てない**
(公式ドキュメント: "When doing stream copy or when -noaccurate_seek is used, it will be preserved")。
つまり素材の先頭は `start` ではなく、**その手前のキーフレーム**である。

実測 (30 秒・GOP 2 秒のテスト動画 / 2026-09-29):

| 確認 | 結果 |
| --- | --- |
| `-ss 10.5 -t 5 -c copy` で切り出す | 先頭フレームは **VOD の 10.0 秒** (要求より 0.5 秒手前) |
| 切り出しの尺 | 5.567 秒 (要求 5.0 秒より長い) |
| 素材の 2.0 秒 と VOD の 12.0 秒 | **PNG の md5 が完全一致** |
| 素材の 2.0 秒 と VOD の 12.5 秒 (`vod_start` を足した場合) | 一致しない |

Twitch の VOD はキーフレーム間隔 2 秒のため、`vod_start` を足すと**最大 2 秒ずれる**。
Shorts の尺では致命的なので、**切り出しの先頭を実測してから足す** (§5.2)。

## 3. 設計

### 3.1 どこで張り替えるか

| 案 | 評価 |
| --- | --- |
| (a) `vertical_builder.build()` の中でアーカイブを判定して張り替える | timeline 層が archive 層を import することになる。`media_recovery` が避けた構造と矛盾する |
| (b) **呼び出し側が「張り替え指定」を作り、`build()` へ渡す** | **採用**。timeline 層は指定の形しか知らない。`media_recovery.recover(source_recover=...)` と同じ流儀 |
| (c) 作成後に縦 Timeline を後から書き換える | 素材プールと切り抜き指定の整合を 2 か所で取ることになる |

張り替え指定は `archive/vod_rebase.py` が作る。

```python
{
  "media":   MediaRef,              # 張り替え先 (元 VOD)
  "offsets": {"m1": 98.5, ...},     # 素材内の秒へ足すと VOD の秒になる
  "source":  {"input_path": ..., "media_path": ..., "media_role": "source"},
  "warnings": ["音量の正規化は引き継ぎません…"],
}
```

### 3.2 控えの無い素材

`source.archive.media` に控えが無い素材 (後から足した動画・画像など) は
**張り替えない**。それらは利用者のファイルを直接指しており消えないため、
そのまま参照させる方が正しい。作成時に件数を知らせる。

### 3.3 切り抜きの指定 (`source["crop"]`)

`crop.is_valid()` は**素材 ID と寸法の一致**を見る (resolve9 §5.3)。
張り替えたまま放っておくと「指定が噛み合わない」として切り抜きごと捨てられ、
横のまま出力されてしまう。そこで張り替え後に指定の `media_id` を向け直す。

寸法が食い違う場合 (中間ファイルは VOD のストリームコピーなので通常は起きない) は
**切り抜きを入れずに作り、知らせる**。resolve9 §4-4「開けないプロジェクトを作らない」に従う。

### 3.4 音量の正規化

アーカイブの素材はクリップごとにラウドネス正規化済みだが、元 VOD は正規化前である。
正規化は 2 パス測定 + 線形適用で、**区間ごとに違う補正量**になるため、
VOD 全体へ当て直すことも、単純なゲインで置き換えることもできない。

初版では**引き継がない**。作成時に必ず知らせる (A7)。
縦プロジェクト側で音量を調整したい場合は、クリップの音声ゲインで調整できる。

### 3.5 `media_role`

縦プロジェクトの `source.media_role` は **`"source"`** にする。
`media_recovery._was_normalized()` はこの値を見て「中間ファイルだったか」を判断し、
`"normalized"` だと素材が見つからないときに**元動画を丸ごと正規化し直そうとする**
(VOD 全体では何時間もかかる)。元動画そのものを指しているので `"source"` が正しい。

## 4. 設計方針

1. **クリップ用の経路に触らない。** `rebase` を渡さなければ `build()` は従来と同じ道を通る (A5)。
2. **切り出しも再エンコードもしない。** 足し算だけで済ませる (resolve9 §4-2 と同じ)。
3. **ずれは実測する。** 推定値 (`vod_start`) ではなく、FFmpeg が実際に切り出した先頭を測る (§5.2)。
4. **落とすものは知らせる。** 音量の正規化・控えの無い素材は作成時に一覧で出す (A7)。
5. **元の Timeline は読むだけ。** 編集中のアーカイブ用 Timeline は 1 つも変えない。

### 5.2 切り出しの先頭を測る

```python
ffprobe -v error -select_streams v:0 -show_packets
        -show_entries packet=pts_time,flags
        -read_intervals "<start-window>%<start>" -of csv=p=0 <vod>
```

* **パケットのフラグ (`K`) だけを見るのでデコードが走らない。** 5 時間の VOD でも 0.1 秒程度。
* 要求位置以前で最も近いキーフレームを採る。`pts_time` は出力順が前後する (B フレーム) ため、
  並びには頼らず最大値を選ぶ。
* 探す幅は `vertical.crop.keyframe_window_sec` (既定 30 秒)。Twitch は 2 秒間隔のため十分に広い。
* **測れなければ `vod_start` をそのまま使う。**作成を止めない (resolve9 §4-4 と同じ)。
* 0 秒は測るまでもないので ffprobe を呼ばない。

### 5.3 素材の張り替え (`vertical_builder._apply_rebase`)

1. `offsets` にある素材を指すクリップだけ、`source_in` / `source_out` へ秒を足し、
   参照先を張り替え先の ID へ向ける。
2. 素材プールは「張り替え先 + 張り替えなかった素材」だけにする。
3. `source` へ `input_path` / `media_path` / `media_role` / `media_id` を書き戻す。
4. `source["archive"]` は従来どおり取り除く (クリップ用として開かせる / resolve9 §3.7)。
5. 切り抜きの指定を向け直す (§3.3)。

ID がぶつからないよう、張り替え先の ID (`"vod"`) が既存の素材と重なる場合は連番を足す。

### 5.4 メニューの出し分け

```python
# TimelineEditorDialog
def _can_make_vertical(self):
    if timeline.orientation == "portrait" or timeline.height >= timeline.width:
        return False
    return self._project_kind() == project_io.project_kind(timeline)

# ArchiveTimelineDialog
def _can_make_vertical(self):
    return super()._can_make_vertical() and os.path.exists(recorded_vod_path(...))
```

* 縦の Timeline からは作れない (resolve9 §10 #10 のまま)。
* **画面の種別と中身の種別が食い違うときは出さない** (従来の判定と同じ効果)。
* アーカイブ用は**元 VOD が無いときだけ出さない**。張り替えられないため。

### 5.5 いつ張り替えるか

`ffprobe` を素材の数だけ呼ぶため、**画面を開くときではなく「作成」を押したときに**測る。
待ちの間は砂時計カーソルにする。失敗は従来どおり「作成できません」のダイアログへ集約する。

## 6. テスト

| 観点 | 確認 |
| --- | --- |
| 張り替えの中身 | 控えのある素材だけが対象。足す値がキーフレーム位置であること |
| キーフレームの解析 | 要求位置以前で最も近いものを選ぶ / 測れなければ要求位置 / 0 秒は呼ばない |
| 時刻 | 素材内 10.0 (控え 100.0 / キーフレーム 98.5) → VOD の 108.5 |
| 素材プール | 「VOD + 張り替えなかった素材」だけになる |
| 種別 | `KIND_CLIP` で、`source.archive` が残らない |
| 切り抜き | 張り替え後も `crop.is_valid()` が真 |
| 非破壊 | 元の Timeline と渡した `layout` が変わらない |
| 従来の動き | 縦キャンバス・0 秒起点への詰め直し・字幕の引き継ぎが変わらない |
| メニュー | 縦/種別違いでは出ない。アーカイブ用 + VOD ありで出る。VOD が無ければ出ない |
| 画面 | 「作成」で VOD を指す縦プロジェクトが書き出される |
