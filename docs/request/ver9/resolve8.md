## 1. どう再現・計測したか

実機の出力を待たずに切り分けられるよう、**実装と同じ手順で ASS を作り、libass に通して画素で測った**。

| 手順 | 中身 |
| --- | --- |
| ASS 生成 | `project_io.load()` → `subtitle_clips()` → `to_item()` → `subtitle_generator.build_subtitle_file()`。出力時 (`compositor.subtitle_chain`) と同じ経路 |
| 描画 | `ffmpeg -f lavfi -i color=black:s=1920x1080:r=60 -vf ass=out.ass -ss <秒> -frames:v 1` |
| 測定 | PNG の輝度から「文字が乗っている y の帯」と「x の範囲」を取る |
| 答え合わせ | 実際の出力 `archive_vod_2910070011_combined.mp4` の同時刻フレームと比較 (一致) |

**重要な注意**: `-ss` を**出力側**に置くこと。入力側に置くと libass がその時刻から動き出すため、
後述する「位置の持ち越し」が起きず**再現しない**。これは不具合の性質そのものでもある (§2.1)。

## 2. 何が起きているか

### 2.1 libass の衝突回避と、位置の持ち越し (これが本体)

ASS 字幕には「同時刻の字幕が重ならないよう、後のものを上へずらす」仕様 (collision detection) がある。
libass では `fix_collisions()` がこれを行い、`detect_collisions` が立っているイベント同士で空き場所を探し
`shift_event()` でずらす。**`\pos` / `\move` を持つイベントはこのフラグが下り、ずらす対象からも、
場所を譲る対象からも外れる** (libass `ass_render.c`)。

さらに libass は**前のフレームで決めた位置を、同じ大きさのイベントならそのまま使い続ける**。
つまり **1 フレームでも重なれば、その瞬間に決まったずれが、そのテロップが消えるまで続く**。

実測 (件 1 /「デラさんの魚は？」と「せせらぎが」の 2 本だけを入れた ASS):

| 時刻 | 「せせらぎが」の位置 | 状況 |
| --- | --- | --- |
| 81.6166 秒 | y 749〜859 | 前のテロップ (y 900〜1012) と重なった 1 フレーム。ここで上へ追い出される |
| 81.65 秒 | y 749〜859 | 前のテロップは既に消えている。**なのに戻らない** |
| 82.0 秒 | y 749〜859 | 同上 |
| 84.0 秒 | y 749〜859 | 消えるまでずっと |

同じ 1 本を単独で描くと y 899〜1009 (= 編集画面と同じ)。**150px 上にいる**。

### 2.2 引き金① ASS 時刻の丸めで、連続しているはずのテロップが 10ms 重なる (件 1)

タイムライン上の値:

```
S1/s28 「デラさんの魚は？」 start=77.266  duration=4.349  → end=81.61500000000001
S1/s29 「せせらぎが」       start=81.615                 → 前の end と隙間ゼロで連続
```

`_format_ass_time()` (`src/modules/subtitle_generator.py:1261`) は `f"{s:05.2f}"`、つまり**四捨五入**である。
浮動小数の誤差で `81.615000…1` は `81.62` へ、`81.615` は `81.61` へ丸まるため、生成される ASS はこうなる。

```
Dialogue: 0,0:01:17.27,0:01:21.62,Streamer,,0,0,0,,デラさんの魚は？
Dialogue: 0,0:01:21.61,0:01:25.04,Sub,,0,0,0,,せせらぎが          ← 10ms 重なる
```

60fps では 81.6166 秒のフレームがちょうどこの 10ms に入る。**その 1 フレームで押し上げが確定する**。
編集画面では隙間ゼロの連続なので、利用者からは「重なっていない」。

本プロジェクト (使用中テロップ 118 本) で、この丸めだけで重なる組は **2 組**。
もう 1 組 (`s4`/`s5`) は相手が `\pos` 付きのため押し上げが起きず、実害は出ていない。

### 2.3 引き金② タイムライン上で実際に重なっている (件 2)

```
S3/s118 「した方がいいんじゃない？何か貰う為に」(2 行) end=457.018
S4/s43  「いやもう、あげるって言ってて・・・」      start=456.967  → 51ms 重なる
```

こちらは丸めではなく編集の結果である。相手が 2 行ぶんの高さを持つため押し上げ量も大きく、
`s43` は 280px 上の y 619〜734 へ飛ばされ、`\pos` 固定の「違う違う違う…」(y 651〜766) と重なった。

### 2.4 なぜ「押し上げた先」で重なるのか

libass は `\pos` 付きイベントを**衝突回避の計算に入れない**。
つまり「上へ避けた先に誰か居る」かどうかを見ていない。本件はどちらも、
押し上げ先にちょうど手で位置を決めたテロップが居たため、避けた結果かえって悪くなった。

### 2.5 なぜ他のテロップでは起きなかったのか

使用中 118 本すべてを突き合わせた集計。

| 条件 | 組数 | 押し上げ | 見え方 |
| --- | --- | --- | --- |
| タイムラインで重なる (片方または両方が `\pos`) | 19 | 起きない | 画面どおり (意図した同時表示) |
| タイムラインで 1ms だけ重なる (両方 `\pos` なし) | 6 | 起きない | ASS の 1/100 秒丸めで重なりが消えるため |
| コメント役割と本文の重なり (両方 `\pos` なし) | 2 | 起きない | コメントは画面中段 (`Alignment=4`)、本文は下段で縦が被らない |
| **下段の既定位置どうしが ASS 上で重なる** | **2** | **起きる** | **報告の 2 件そのもの** |

つまり「他のテロップでは重なっていない」という報告は正しく、**条件がそろった 2 件だけ**が壊れていた。
t=23.5 / 135.5 / 162.5 / 202.5 / 251.5 / 331.5 / 170.5 / 495.5 秒でも
「通し描画」と「その時刻だけの描画」が完全一致することを確認した (押し上げなし)。

### 2.6 なぜ編集画面では見えないのか

| 出口 | 配置の決め方 | 衝突回避 |
| --- | --- | --- |
| Timeline のプレビュー (Qt) | `preview_items.default_subtitle_anchor()` + `_place()` で `Alignment`/`Margin` から直接置く (`preview_items.py:99,524`) | **しない** (常に既定位置) |
| 高精度プレビュー (1 枚絵) | 同じ ASS を libass で描くが、**その時刻だけを描く**ため前フレームからの持ち越しが無い | 事実上効かない |
| Resolve 書き出し | `resolve_export._title_position()` が `Alignment`/`Margin` から座標を計算 (`resolve_export.py:142`) | **しない** |
| **動画出力 (ASS 焼き込み)** | libass が決める | **する** ← ここだけ違う |

編集画面・静止プレビュー・Resolve はすべて「既定位置」で一致していて、**動画出力だけが例外**だった。

## 3. 対策

### 3.1 方針

**画面が正。libass に位置を決めさせない。**
テロップの位置は既にアプリ側 (設定の `Alignment`/`Margin`、またはドラッグした `transform`) で決まっている。
ASS にそれを**明示的に書く**ことで、libass の自動配置が入り込む余地を無くす。
重なる・重ならないはプレビューで見たとおりになり、出力と食い違わなくなる。

### 3.2 対策 1 (本命): 既定位置のテロップにも `\an` + `\pos` を書く

いまは `transform` を持つテロップだけ `{\an5\pos(x,y)}` が付き、
位置未指定のテロップはタグ無しで Style の `Alignment`/`Margin` 任せになっている
(`_inline_position_override()` / `src/modules/subtitle_generator.py:1018`)。
これを**位置未指定のときも既定のアンカー点を計算して出す**ように変える。

#### 3.2-1 アンカーの式 (実測で確定)

`W`/`H` は `PlayResX`/`PlayResY`、余白は役割ごとの値 (`FontProfile.placement_for_role()`)。

| 配置 (`Alignment`) | 書き出すタグ | x | y |
| --- | --- | --- | --- |
| 1 / 4 / 7 (左) | `\an{alignment}\pos(x,y)` | `margin_l` | ↓ |
| 2 / 5 / 8 (中央) | 同上 | `(margin_l + W - margin_r) / 2` | ↓ |
| 3 / 6 / 9 (右) | 同上 | `W - margin_r` | ↓ |
| 1 / 2 / 3 (下段) | — | — | `H - margin_v` |
| 4 / 5 / 6 (中段) | — | — | `H / 2` |
| 7 / 8 / 9 (上段) | — | — | `margin_v` |

- 中央揃えが左右余白を含むことは実測で確かめた (`MarginL`/`MarginR` を 40/40 → 40/240 にすると
  中心が 962 → 862 へ動く。式どおり `(40 + 1920 - 240) / 2 = 860`)。
- **アンカーを `\an5` (中央) に寄せず、元の `Alignment` の番号をそのまま使う**のが肝である。
  下段系なら「行の下端」が基準になるので、**行数が変わってもずれない**。

#### 3.2-2 既定配置と一致することの実測

| ケース | タグ無し (現行) | `\an{配置}\pos(…)` 付き | 判定 |
| --- | --- | --- | --- |
| 1 行 / Sub (`\an2\pos(960,1020)`) | y 899〜1009 / x 752〜1172 | y 899〜1009 / x 752〜1172 | 完全一致 |
| 2 行 / Sub (`\an2\pos(960,1020)`) | y 769〜883・903〜1013 / x 379〜1547 | 同左 | 完全一致 |
| コメント / `Alignment=4` (`\an4\pos(240,540)`) | y 498〜588 / x 245〜1047 | 同左 | 完全一致 |

**見た目は 1px も変わらない。変わるのは「libass が勝手に動かさなくなる」ことだけ**である。

#### 3.2-3 効果の実測

| 条件 | t=84.0 (件 1) | t=460.5 (件 2) |
| --- | --- | --- |
| 現行 | y 749〜873 の 1 かたまり = **重なり** | y 619〜766 と 788〜895 = **重なり** |
| 対策 1 適用 | y 762〜873 と 899〜1009 = **解消** | y 651〜766 と 788〜1014 = **解消 (画面と同じ配置)** |

#### 3.2-4 文字寄せ (ver9 resolve3) との整合

いまは「位置指定なし + 文字寄せあり」のとき、箱を**イベント余白 (`Dialogue` 行の MarginL/MarginR)** で表し
`\an` だけを足している (`resolve_line_align()` / `subtitle_generator.py:836`)。
`\pos` を書くとイベント余白は無視されるため、ここは **`\pos` 経路と同じ扱いへ寄せる**。

- 文字寄せが効く場合 (最長行の幅 `width` が実測できている):
  既存の `\pos` 側の分岐と同じく、箱の左端 `box_left` からアンカーを左/中央/右へ移して `\pos` の x を決める
  (`_inline_position_override()` の `align` 分岐をそのまま使う)。`Dialogue` 行の余白は `0,0,0` へ戻す。
- 幅が測れずスキップになる場合 (`require_measured_font` / `overflow`):
  **文字寄せは現行どおり効かせない**まま、既定アンカーの `\pos` だけ書く。
  いまも効いていないので後退はしない。

#### 3.2-5 コメント役割との整合

コメントは `Alignment=4` + `comment_margin_l=240`、背景 (角丸) とアイコンの座標は
`comment_decor` が**位置指定なしのときの既定位置を推定して**決めている (`comment_decor.py:186-205`)。
その推定式と §3.2-1 の式は同じ基準 (左端 = `comment_margin_l` / 中心 = `H/2`) なので、
`\an4\pos(240,540)` を書いても背景・アイコンとずれない (§3.2-2 の実測でも一致)。
**むしろ現状はコメント本文だけが押し上げられて背景が取り残される危険があり、対策 1 はそれも塞ぐ。**

#### 3.2-6 設定

ハードコードを避け、`setting.json` の `subtitle` へ切り替えを 1 つ足す (既定 `true`)。

```jsonc
"subtitle": {
  // テロップの位置を ASS へ明示的に書く (libass の自動ずらしを止める / ver9 resolve8)
  // false にすると従来どおり libass 任せになる
  "explicit_position": true
}
```

`settings_window.py` への露出は必須ではない (不具合の修正であり、通常は切り替えない)。
`setting.json` のキーと既定値マージだけ用意する。

### 3.3 対策 2: ASS 時刻の丸めを切り捨てへ

`_format_ass_time()` (`subtitle_generator.py:1261`) の `f"{s:05.2f}"` は四捨五入で、
§2.2 のとおり**隣り合うテロップが 1/100 秒だけ重なる**ことがある。
**秒 → ミリ秒へ丸めてから 1/100 秒へ切り捨てる**形にすれば、同じ境界値は必ず同じ値になり重ならない。

```python
# 1/100 秒へ切り捨てる (浮動小数の誤差はミリ秒で吸収してから落とす)
cs = math.floor(round(seconds * 1000) / 10)
```

- 表示は最大 10ms (60fps で 0.6 フレーム) 短くなるだけで、実害は無い。
- `start` と同じ値まで切り捨てられて**尺ゼロ**になるテロップ (10ms 未満) は、
  `end = start + 0.01` へ持ち上げて落とさないようにする。
- 対策 1 が入れば押し上げ自体が起きないが、「1 フレームだけ 2 本出る」状態そのものを消せるので併せて直す。

### 3.4 対策 3: 保存時の丸めで隣り合うテロップを重ねない

`SubtitleClip.to_dict()` は `timeline_start` と `duration` を**別々に** `round_sec()` (小数 3 桁) している
(`src/timeline/model.py:376` / `round_sec` は `model.py:99`)。
このため保存・再読込を経ると「前の終わり」と「次の始まり」が最大 1ms ずれ、重なりが生まれる
(本プロジェクトに 6 組ある)。

```python
# 終端を保ったまま尺を丸める (開始と終端をそれぞれ丸めてから差を取る)
start = round_sec(self.timeline_start)
duration = round_sec(self.timeline_start + self.duration) - start
```

映像クリップ (`Clip.to_dict()`) も同じ作りだが、そちらは尺が素材の切り出し長と結び付くため、
**今回は字幕クリップだけに留める**のが安全である (§7 で確認)。

### 3.5 対策 4 (任意): 編集画面で重なりを知らせる

対策 1 を入れると「画面で重なっていれば、出力でも重なったまま出る」= 画面と一致する。
その代わり libass が勝手に避けてくれることも無くなるので、
**件 2 のように利用者が 51ms 重ねてしまった事故**は画面で気づける必要がある。

- 同じ既定位置 (位置指定なし・同じ役割配置) のテロップが時間で重なっているとき、
  タイムラインのクリップに注意色を出す / ステータスに件数を出す。
- 判定は `Timeline.subtitle_clips()` を時間順に見て隣を比べるだけで、計算量は無視できる
  (本件 118 本で 1ms 未満)。

### 3.6 採らなかった案

| 案 | なぜ採らないか |
| --- | --- |
| `Dialogue` の Layer をテロップごとに変える | 実測では確かに押し上げが止まる (t=84.0 で解消) が、「Layer が違えば衝突回避しない」は libass の実装に依存した挙動で仕様の保証が無い。コメント背景/本文の Layer 規約 (`comment_bg_layer`/`comment_text_layer`) とも干渉する |
| `[Script Info]` に `Collisions:` を書く | `Normal`/`Reverse` の切り替えしかなく、**無効化はできない** |
| 重なったテロップの時刻を出力時に自動で詰める | 利用者が意図して重ねた同時表示 (本件にも 19 組ある) を壊す |

## 6. 影響範囲とリスク

| 項目 | 見立て |
