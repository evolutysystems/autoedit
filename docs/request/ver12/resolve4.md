## 0. 先に結論

| # | 事項 | 結論 |
| --- | --- | --- |
| **A** | 書き出し (出力) の比率 | **壊れていない**。`compositor.base_zoom_filters` は crop / pad でキャンバス寸法へ必ず収める。縦横比も保たれる (§2 で実測) |
| **B** | 壊れて見えるのはどこか | **編集画面のプレビュー表示だけ**。拡大した映像がキャンバス枠 (1080x1920 / 1920x1080) の**外へ溢れて描かれている** |
| **C** | 原因 | `BaseFrameItem` を**キャンバス矩形でクリップしていない**。`QGraphicsView.fitInView` はシーン矩形を収めるだけで、枠外のアイテムも描くため、ビューポートの余白 (縦動画なら左右の黒地) が映像で埋まる |
| **D** | 修正 | **プレビューの V1 をキャンバス矩形でクリップする** (R1/R2)。倍率そのものは制限しない。「範囲内でズーム」= 枠の中だけを見せる、という解釈 (§7 Q1 で確認) |

要点は **「プレビューだけが出力と食い違っている」**。拡大率は出力側では
「収めた寸法の z 倍へ scale → キャンバス寸法で crop」という手順で、はみ出しを**切っている**。
プレビューは同じ倍率を `QGraphicsPixmapItem.setScale` で掛けるだけで、切っていない。
300% ではキャンバスの 3 倍の面積を占めるため、枠の外が全部映像になる。

## 1. 現象と再現

再現手順 (2026-11-27 のログで確認した条件):

1. クリップ用タブへ縦動画をドラッグ＆ドロップする
   (実測: 入力 918x1632 → `output_profile` が「縦動画と判定 (出力=1080x1920)」)
2. 編集画面で V1 のクリップを選ぶ
3. 「拡大率」を **300%** (`timeline.base_zoom.max` = 3.0 の上限) にする
4. プレビューの縦枠 (1080x1920) が分からなくなり、左右の余白まで映像で埋まる

**ログ上の裏取り** (`src/gui/logs/autoedit_20261127.log`)

```
14:01:33 src.modules.output_profile: 縦動画と判定 (入力=918x1632 → 出力=1080x1920)
14:02:08 src.timeline.builder: Timeline 構築: ... / 60fps 1080x1920
```

プロジェクト (`20261127_..._portrait.timeline.json`) の `crop` は `null`、素材は 918x1632。
つまり**切り抜き指定のない縦動画プロジェクト**であり、拡大率が有効な経路に入る
(切り抜き指定があるときは拡大率は使えない / resolve6 §3.6、`_show_base_zoom` が欄を無効化する)。

## 2. 出力側は正しい (変更しない)

`src/timeline/compositor.py:243` `base_zoom_filters` を実際に通して得たフィルタ列。

| キャンバス | 素材 | 倍率 | 生成されるフィルタ |
| --- | --- | --- | --- |
| 1080x1920 | 1080x1920 | 300% | `scale=3240:5760` → `crop=1080:1920:1080:1920` |
| 1080x1920 | 1920x1080 | 300% | `scale=3240:1818` → `crop=1080:1818:1080:0` → `pad=1080:1920:0:51:black` |
| 1920x1080 | 1080x1920 | 300% | `scale=1818:3240` → `crop=1818:1080:0:1080` → `pad=1920:1080:51:0:black` |

いずれも **最後は必ずキャンバス寸法** (1080x1920 / 1920x1080) で、縦横比も保たれている
(`tests/test_base_zoom.py` の `test_aspect_ratio_is_kept` / `test_sizes_are_even` が既に守っている)。
**よって出力の仕様は変えない。** 直すのは表示だけである。

## 3. 原因 (証拠つき)

### 3.1 プレビューは倍率をアイテムの `scale` で掛けるだけ

`src/gui/timeline/preview_panel.py:698-719` (`_on_frame_ready`)

* `scale = min(canvas_w / pixmap_w, canvas_h / pixmap_h)` … キャンバスへ収める倍率
* `zoom` … `_base_zoom_view()` が返す拡大率 (`preview_panel.py:735`)
* `self._base_item.setScale(scale * zoom)` + 中央寄せの `setPos`

ここに **crop に相当する処理が無い**。拡大したぶんはそのまま外へ出る。

### 3.2 枠外も描かれる

* シーン矩形はキャンバスと同じ `setSceneRect(0, 0, canvas_w, canvas_h)` (`preview_panel.py:281`)
* ビューは `fitInView(sceneRect, KeepAspectRatio)` (`preview_panel.py:1683`)
* `QGraphicsView` は**シーン矩形の外にあるアイテムも描く** (シーン矩形はスクロール範囲の定義でしかない)
* `BaseFrameItem` (`preview_items.py:907`) に `ItemClipsToShape` も親アイテムでのクリップも無い

実測 (オフscreen で確認。キャンバス 1080x1920 / 素材 918x1632 / 300%):

```
item.sceneBoundingRect() = QRectF(-1080, -1920, 3240, 5760)
scene.sceneRect()        = QRectF(0, 0, 1080, 1920)
シーン座標 (-900, 800) 付近を描画 → 映像の画素が出る (= 枠外に溢れている)
```

縦動画はビューポートが横長なので、枠の左右に**キャンバス幅ぶんの余白**がある。
300% では映像がその余白を完全に覆うため、1080x1920 の枠が見えなくなる。
これが「縦動画の比率が壊れた」という見え方である。

### 3.3 影響範囲 (壊れていないもの)

| 経路 | 状態 | 理由 |
| --- | --- | --- |
| 書き出し | 正常 | §2 |
| プロキシのタイル由来のプレビュー | 正常 | タイルに crop まで焼かれており、パネル側は倍率を掛けない (`from_proxy` 判定 / `preview_panel.py:706`) |
| 高精度プレビュー | 正常 | `still_filters` を通した本番と同じ絵 |
| 下書き (フレーム直取り) のプレビュー | **溢れる** | 本書の対象 |

## 4. 修正設計

### R1. `BaseFrameItem` にキャンバス枠のクリップを持たせる (`preview_items.py`)

```
class BaseFrameItem(QGraphicsPixmapItem):
    # 描画をキャンバス枠の中だけに限る矩形 (シーン座標 / None なら従来どおり無制限)
    _canvas_clip = None

    def set_canvas_clip(self, canvas_size):   # (w, h) または None
    def paint(self, painter, option, widget=None):
        # 枠が指定されていればシーン矩形→アイテム座標へ写してクリップしてから描く
```

* クリップ矩形は `mapRectFromScene()` でアイテム座標へ写す (回転は無いため矩形のまま写る)
* `set_canvas_clip(None)` で従来の描画に戻せる (既存実装を壊さないための退避口)
* `boundingRect()` は変えない。再描画範囲が広いだけで害が無く、
  当たり判定 (ドラッグで位置を変える操作) も現状のまま保てる

**倍率の上限は変えない。** 300% の意味は「収めた状態の 3 倍」であり、
枠の中だけを見せれば出力と一致する (§2 の crop と同じ見え方になる)。

### R2. パネルがキャンバス寸法を渡す (`preview_panel.py`)

* `_build_ui()` で `self._base_item.set_canvas_clip(self._canvas)` を 1 回呼ぶ
* `self._canvas` は `controller.timeline.width / height` 由来 (`preview_panel.py:175`)。
  **1920 / 1080 はコードに書かない** (ハードコード禁止)。
  縦横の値は出力プロファイル (`src/modules/output_profile.py` → `builder.build`) が決めたものを使う
* キャンバス寸法が変わる場面 (プロジェクト切り替え) では `_canvas` の更新箇所に合わせて再設定する

### R3. ドラッグ範囲は変更しない

`_base_drag_bounds` (`preview_panel.py:748`) は「はみ出し量の半分」を可動範囲にしており、
出力側の `commands.clamp_base_offset` と同じ範囲である。クリップを入れても範囲は変わらない。
クリップ後は**掴んで動かした結果が出力の crop 位置とそのまま一致**する (今は溢れぶんがおまけで見えている)。

### R4. 設定値は追加しない

枠はキャンバス寸法そのもので、選択肢が無い (枠外を見せる/見せないは仕様の是非ではなく出力との一致)。
したがって `setting.json` へ新しいキーは足さない。
将来「編集中だけ枠外を薄く見せたい」という要望が出た場合に限り
`timeline.preview.show_outside_canvas` (既定 false) を足す形にできる — 今回は入れない (§7 Q2)。

## 5. 採らなかった案

| 案 | 内容 | 採らない理由 |
| --- | --- | --- |
| 最大倍率を下げる | `base_zoom.max` を 1.0 近辺へ制限し、枠からはみ出さない範囲だけ許す | 「寄りで見せる」機能そのものが成立しない。出力は正しく crop できているので制限する理由が無い |
| 親アイテムでクリップ | キャンバス大の矩形アイテムを作り `ItemClipsChildrenToShape` を立てて V1 を子にする | アイテムの親子関係が変わり、座標・選択・ドラッグの既存コードに広く影響する。R1 のほうが変更が小さい |
| ビューポートの余白を黒で覆う | 枠の外側にマスクを重ねる | 重ねる順番 (Z 値) の管理が増え、オーバーレイやテロップの見え方に影響する |
| プレビューも ffmpeg で crop する | フレーム取得時に `still_filters` を通す | 1 コマごとに重くなる。resolve6 §5.8 が `setScale` を選んだ理由 (再生中の費用) に反する |
