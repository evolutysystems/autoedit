| 確認したこと | 結果 |

### 2.2 動画どおりにはできないもの (近似)

| 項目 | 理由 | 近似 |
| --- | --- | --- |
| 横方向だけのブラー (発光ブラー・EZ) | ASS の `\blur` は縦横同じ | 横へ伸ばす (`\fscx`) / 普通のぼかし |
| ぴかっとの斜めの光 | `\clip` は軸に平行な矩形 (斜めは描画クリップが要り重い) | 縦の帯 |
| イーズ (なめらかな減速) | `\t` の加速度指定はプレビューと一致させにくい | 直線区間を細かく刻む (`ease_segments`) |

## 3. 方式: キーフレーム

すべての動きを「時刻と状態の組」(キーフレーム) で表す。状態は次の 12 項目。

| 項目 | 意味 | ASS |
| --- | --- | --- |
| `dx` / `dy` | 位置のずれ (px) | `\move` |
| `sx` / `sy` | 拡大率 (%) | `\fscx` / `\fscy` |
| `rot` | 回転 (度) | `\frz` |
| `blur` | ぼかし (px) | `\blur` |
| `opacity` | 不透明度 | `\1a` `\3a` `\4a` (元のアルファを保って薄める) |
| `white` / `dark` | 塗りと縁を白 / 黒へ寄せる量 | `\1c` `\3c` |
| `bord` | 縁を太らせる量 (px) | `\bord` |
| `clip_l` / `clip_r` | 文字の塊の幅に対する表示範囲 | `\clip` |

* ASS: キーとキーの区間ごとに 1 イベント。始点の値を書き、`\t(0,区間長, 終点の値)` で補間させる
  (位置は `\move`)。最後のキーの後は、残る層だけ静止イベントで表示終わりまで出す。
* プレビュー: 同じキーを `state_at()` で直線補間して描く。**キーは 1 か所 (`spec()`) でしか作らない**。
* 1 本のテロップは**層**の重ね (下から)。衝撃1 = 光の箱 + 本文、衝撃2 = 本文 + 残像、
  ぴかっと = 本文 + 光の帯。光・残像の層は動き終わると消える。
* フェードは区間ごとのイベントへ `\fade` (7 引数) を付け、テロップ開始からのずれを引いた時刻にする。
  `\fad` を区間ごとに付けると区間ごとに点滅するため。

## 5. 位置の基準

拡大・回転は基準点を中心に掛かるため、下段基準 (`\an1〜3`) のままだと字が下端から伸びる。
動きを付けたテロップは**上下だけ中央 (`\an4〜6`) へ移し、y を塊の高さの半分ずらす**
(塊の高さ = 行数 x Fontsize / §2.1 で実測)。左右の寄せは変えない (複数行の行ごとの寄せを保つ)。
動き終わった状態は、動きなしのテロップと同じ位置になる。

`clip_in` などの表示範囲と波打ちの文字位置は、フォントの実測送り幅 (`font_advance`) で
文字の塊の左右の端を求める。測れないフォントでは、表示範囲は画面幅を代わりに使い、
波打ちは行全体の上下動へ落とす (警告を 1 回出す)。

## 6. 負荷と保護

| 種類 | 1 本あたりの Dialogue 行 (2 秒のテロップ) |
| --- | --- |
| 減速系 (発光・EZ・黒ブラーなど) | 7 前後 |
| ポヨン・つっこみ・飛び込みツッコミ | 3〜8 |
| 震える | 約 40 (50ms 刻み) |
| 波打ち | 文字数 x 約 29 (70ms 刻み) |

`max_events_per_clip` (既定 120) を超えそうな震える・波打ちは刻みを粗くして収める。
波打ちで波の形が崩れるほど粗くなる (刻み > 周期の 1/4) ときは、行全体の上下動へ落とす。

## 11. 不具合: 種類を選んだあとアニメーションの欄が無効になる (2026-11-20)

### 症状 (利用者)

「クリッピング登場」を選んだあと、アニメーションのコンボが無効 (灰色) になり変えられなくなった。
「ぴかっと」でも同じ。

### 原因

利用者のログ (`src/gui/logs/autoedit_20261120.log`) で、**種類を選んだのと同じ瞬間に
テロップがコメント用トラック (S2) へ移り、役割がコメントになっていた**。

```
10:30:29.537 移動先に合わせて役割を comment にしました: s2   (S3 → S2)
10:30:29.636 フォントの送り幅を読みました …                    (動きの組み立て = 種類の変更と同時)
10:32:54.139 移動先に合わせて役割を comment にしました: s379 (S3 → S2 / ぴかっと)
```

コメントは「フェードのみ」(resolve2 §12 ②) のため、コンボが無効になるのは仕様どおりの表示。
問題は**意図しないトラック移動**のほう。

Timeline (`TimelineView`) はマウス追跡が有効で、`mouseMoveEvent` が**ボタンを押しているかを
見ていなかった**。クリップを押したときの「離した」通知を取りこぼすとドラッグが残り、
ボタンを押していない移動 (インスペクタへカーソルを運ぶ途中で S2 の行を通る) でドロップ先が
S2 に変わり、次に離した瞬間 (コンボの項目の選択) に移動が確定していた。
取りこぼしのきっかけ自体は Linux の検証環境では再現できていない (Windows のポップアップ
の扱いに依存する可能性がある)。

### 対策

| 置き場 | 内容 |
| --- | --- |
| `gui/timeline/timeline_view.py` `mouseMoveEvent` | ドラッグ中なのに左ボタンが押されていない移動が来たら、**確定せずにドラッグを捨てる** (`_cancel_drag`) |
| 同 `mouseReleaseEvent` | 左ボタン以外を離してもドラッグを確定しない |
| `tests/test_subtitle_track_edit.py` `StaleDragTest` | 取りこぼし後のボタンなしの移動で移らないこと / 右ボタンで確定しないこと (修正前は 2 件とも失敗) |

コメント用トラックへ移ってしまったテロップは、S1 などへドラッグで戻せばアニメーションを選べるようになる。

## 12. 「続きから」の一覧で開いたらそのまま再開する (2026-11-20)

### 要望 (利用者)

クリップ用で保存して閉じたあと、「続きから」の一覧でプロジェクトを開いても始まらない。
一覧で「開く」(ダブルクリック) を押したら、そのまま「実行」を押した処理へ進んでほしい。
アーカイブ用でも同じなら一緒に直す。

### 調べたこと

* ログ (`src/gui/logs/autoedit_20261120.log`) とサムネイル (`src/settings/project_thumbs/6cf4b3a8…`) から、
  10:51:08 に一覧が開き、そのプロジェクトの概要も読めていた。読み込みの失敗ではない。
* クリップ用タブの一覧は **選択状態にするだけ** (ver3 resolve15 §3-6) で、続けて「実行」を押す必要があった。
* アーカイブ用タブの一覧は以前から **開いたらそのまま再開** する (`archive_tab._on_library_open` → `_start_resume`)。
  → 直すのはクリップ用だけ。

### 対策

| 置き場 | 内容 |
| --- | --- |
| `gui/main_window.py` `ClipTabWidget._open_library` | 一覧で選ばれたら `_open_project` (選択 → `_on_run`) へ進む。再開は一覧画面を閉じきってから始める (自動保存の確認・編集画面が閉じかけの一覧と重ならないように) |
| 同 (一覧を無効にした設定のファイル選択) | 選んだら同じく再開する (一覧の「開く」と同じ操作のため) |
| 同 `select_project` | 選択できたかを返すようにした。**選択するだけで実行はしない**のは従来どおり (アーカイブ用タブから種別違いで回ってきたときに使うため) |
| 「続きから」のツールチップ | 「保存した Timeline プロジェクトを一覧から選び、編集の続きを開きます」(英語も更新) |
| `tests/test_clip_tab_selection.py` `LibraryOpenTest` | 一覧の「開く」で再開が始まる / 閉じただけでは何も始まらない / `select_project` 単独では実行しない (修正前は 2 件失敗) |

D&D でプロジェクトを落としたときは従来どおり選択状態になり、「実行」で始まる (案内文もそのまま)。
