## Stretheus v1.5.9 (CPU版・インストーラー配布)

`StretheusSetup.exe` をダウンロードして実行してください。インストーラーが本体を自動取得・展開します。

> 今回は **容量まわりのクラッシュ対策**、**テロップの切れ目と発話カットの一致**、
> **プレビューと出力の見え方の一致**、**コメント背景のはみ出し**が中心です。
> いずれも利用者からの報告に対する対応です。

---

### 修正（容量不足で「スクリプトを実行できません」と落ちました）

Twitch VOD の取得中に C: ドライブが埋まると、
`Failed to execute script 'main_window' ... [Errno 28] No space left on device`
というダイアログでアプリごと落ちていました。取得処理は本体 exe を再呼び出しして動かしており、
その経路に例外の受け口が無かったためです。

v1.5.9 では次のように変えました。

- **始める前に空き容量を確かめます。** 作業先と出力先の空きが `general.min_free_space_gb`（既定 20GB）
  を下回っていれば、処理を始める前に「空き容量が足りません（場所／空き／必要）」と出します。
- 途中で埋まった場合も**クラッシュではなく「容量不足」の文言**で止まります。FFmpeg の標準エラーも
  見るため、FFmpeg 側で埋まった場合も理由が分かります。
- **起動のたびに古い作業フォルダの残骸を片づけます**（`general.cleanup_stale_work_hours`、既定 24 時間より
  古いものだけ）。異常終了で残った中間ファイルが溜まり続けて、次回さらに空きが減る悪循環を断ちます。

### 修正（取得した配信データが見えない場所に溜まり続けました）

取得した VOD（1 本 10〜25GB）と取得中の断片が、**インストールフォルダ配下と
`%LOCALAPPDATA%\twitch-dl`** に置かれ、どちらも自動では消えませんでした。
開発端末では合計約 94GB が滞留していました。

- 取得物の置き場を **`%LOCALAPPDATA%\Stretheus\archive_work`** へ移しました。
  Twitch のログイン情報は新しい置き場へ引き継ぐため、ログインし直す必要はありません。
- 取得中の断片を作業フォルダ配下（`archive_work\cache`）へ移し、管理下に置きました。
- **旧版が残したデータは、起動時に一度だけお尋ねします。**「以前の保存先に残った配信データ」
  「取得時の一時データ」が 1GB 以上あるときだけ尋ね、**同意いただいた場合にゴミ箱へ送ります**
  （完全削除はしません／一度答えると二度は尋ねません）。
- 元 VOD は、**それを元にした自己完結プロジェクトが保存されている**ときだけ不要と判定し、
  ゴミ箱へ送ります。残したい場合は `archive.download.keep_vod` を `true` にしてください。
- アンインストール時に `%LOCALAPPDATA%\Stretheus\archive_work` も削除します
  （編集結果・出力動画は利用者が選んだ別フォルダにあるため残ります）。

### 修正（`処理に失敗しました。ffprobeが失敗。` と出て先へ進めませんでした）

前回の取得が途中で終わると、中途半端な `vod_<id>.mp4` が残ります。これまでは
`--skip-existing` によって**それを「取得済み」として素通り**させ、採点の最初の尺取得で落ちていました。

v1.5.9 では**使える mp4 かどうかを自前で確かめてから**判断し、壊れていれば取り直します。
失敗時の文言にも、どの段階で何が起きたかを載せるようにしました。

### 変更（テロップが細かく裁断され、発話カットの先頭と合いませんでした）

これまでは「カットごとに必ずテロップ 1 本」に寄せていたため、文脈が続いているのに
切られる箇所が多くありました。v1.5.9 では**テロップの単位を文字数で決めます**
（`subtitle.subtitle_unit = "length"`）。

- 下限（`subtitle.min_line_length`）に達するまでは**カットを跨いで繋ぎます**。
- 上限（`max_line_length × subtitle_max_lines`）を超える場合は**カット内でも切ります**。
- 下限に達したあとは**文末記号（。．！？!?）で区切ります**。
- 各カットの先頭テロップは**カット頭へ揃えます**（`align_to_cut_head`）。
- Timeline 編集画面に**「テロップをカット頭へ揃える」（Ctrl+Shift+A）**を追加しました。
- 無声子音でカットの外へこぼれた語を拾うようにしたため、テロップの頭が 1 文字欠ける現象も直ります。

> 裁断が多いと感じる場合は `subtitle.min_line_length` を上げてください（一次の調整つまみです）。

### 修正（プレビューと出力で字幕の大きさ・行送りが違いました）

libass（出力）は Fontsize を `usWinAscent + usWinDescent` 基準でスケールしますが、
プレビュー（Qt）は em 基準で描いていたため、**同じ設定でもプレビューの字が約 8% 大きく**、
行送りも 1 行あたり約 13px 上へずれていました。

- プレビュー側でフォントの縦メトリクスを読み、**libass と同じ字の大きさ・行送り**で描きます。
- 字間（`subtitle.spacing`）もプレビューへ反映します。
- 再生ヘッドを置いて Space を押すと**再生ヘッドがかなり前へ戻る**不具合を直しました
  （シーク完了前の位置通知を書き戻していたためです）。
- 再生中に**4 秒ごとに画面が暗転してチカチカする**不具合を直しました。プロキシ（編集内容を
  当てた低解像度の動画）をタイルで繋いで再生しており、その継ぎ目で映像面が一瞬空になって
  いました。再生中は近似描画へ、**停止・コマ送り・スクラブでは従来どおりプロキシの絵**を使います
  （`timeline.preview.proxy.mode` の既定を `off` へ変更。更新時も一度だけ自動で寄せます）。

### 修正（コメント役割のテロップが背景の黒い箱からはみ出しました）

背景の箱の幅を、**フォントを見ずに固定係数**（全角 0.78 / 半角 0.45）で見積もっていました。
この係数はフォントごとに 1.5 倍以上違い、にくまるフォントでは全角だけで 1.19 倍、
`W` のような字では 2 倍以上足りませんでした。

v1.5.9 では**フォントファイルから 1 文字ずつの送り幅を読んで**箱の幅を決めます
（`subtitle.comment_bg_measure_font`）。縁取りの張り出しも箱に含めます
（`comment_bg_include_outline`）。フォントを読めない場合は従来の固定係数へ落ちるため、
**どのフォントでも処理が止まることはありません**。

### 修正（アーカイブ編集まわりの不具合）

- 「セクション追加」直後に `AttributeError: 'NoneType' ... setLabelText` が出る不具合を直しました。
- セクション追加 → Timeline を閉じる → メイン画面を閉じる、の順で
  `libshiboken: Internal C++ object ... already deleted` が出る不具合を直しました。
- アーカイブプロジェクトを**保存するたびに `.media` 内の素材が複製されて増える**不具合を直しました
  （`m1_normalized.mp4` → `m1_m1_normalized.mp4` のように名前が伸びていました）。
- 保存した自己完結プロジェクトを「編集の続き」から開くと**「素材が見つかりません」**になる不具合を直しました。
- 保存済みプロジェクトからでも**イントロカードを作り直せる**ようにしました（素の控えを保存します）。
- 「編集の続き」の履歴に**同じプロジェクトが 2 行並ぶ**不具合を直しました。
- 区間追加の既定を見直しました（埋まっている区間の判定・隣接区間の統合・上限 20 区間）。

### 変更（ぼかしの編集 UI を既定で出しません）

`blur.ui_enabled`（既定 `false`）を追加し、**ぼかしの設定タブと Timeline 編集画面の
「ぼかし...」ボタンを既定で出さない**ようにしました。
焼き込みは `blur.enabled` だけを見るため、**すでに保存済みのぼかし指定は従来どおり出力に掛かります**。
再び使う場合は `setting.json` の `blur.ui_enabled` を `true` にしてください。

### 動作要件

- Windows 11 / 64bit。音声認識とぼかしの解析は CPU で行います（CUDA は同梱していません）。
  初回は Whisper モデルを自動でダウンロードするため、ネット接続が必要です。
- 編集を始める前に**空き容量 20GB 以上**を確かめます（`general.min_free_space_gb` で変更可）。
  Twitch VOD の取得を行う場合は、VOD 1 本の 2 倍程度の空きを見ておいてください。
- FFmpeg/ffprobe・twitch-dl・ぼかし用モデル（YOLOX-Tiny）・VAD モデル（Silero VAD）は同梱済みです。

### 更新について

- 既存インストールの `setting.json`（出力先など）は保持されます。新しいキーは起動時に自動で書き足されます。
- 保存済みプロジェクト（`.timeline.json`）は v1.5.8 のものをそのまま開けます。書式は変えていません。
- **初回起動時に、旧版が残した配信データの回収をお尋ねします**（1GB 以上あるときだけ）。
  同意すると**ゴミ箱へ**送ります。すぐに容量を戻したい場合はゴミ箱も空にしてください。
- テロップの切れ目は**既存の `subtitle.min_line_length` の値**を下限として決まります
  （v1.5.8 の既定は 15、新規インストールは 5）。切れ目を細かくしたい場合は値を下げてください。
- プレビューの暗転対策（`timeline.preview.proxy.mode`）は、`tile` のまま残っている環境を
  起動時に一度だけ `off` へ寄せます。寄せたあとに `tile` へ戻した場合は二度と書き換えません。
- 全テスト 1,595 件が通ることを確認しています。

### 確認方法（ダウンロードしたファイルが壊れていないか）

インストーラーは、取得した本体 zip の **SHA-256 を自動で検証**します。
検証に失敗した場合はインストールを中止します。

`StretheusSetup.exe` の SHA-256 は次の値です。気になる場合は照合してください。

```
13CDB27C962513D33BDED77E2670A84A99FE7AC1BBB254D670FB9265099F72E1
```

```powershell
(Get-FileHash .\StretheusSetup.exe -Algorithm SHA256).Hash
```
